# ADR-0020 · 最终确认数据标准为一级产品域

## 状态 · Status

Accepted

## Supersedes

[ADR-0019](./0019-finalize-data-standards-as-assets.md)。本决策以访谈的最终确认恢复并收敛 [ADR-0018](./0018-restore-data-standard-as-top-level-product.md) 的边界。

## 背景 · Context

需求访谈中曾讨论把数据标准作为数据资产发布并允许外部系统或人员申请使用，随后明确撤回该流程；最终要求是：数据标准为一级菜单，五项能力放二级；本期不考虑数据标准资产流程；旧标准功能按新设计删除，不兼容；标准只需简单版本查看和追溯。

## 决策 · Decision

数据标准建设为独立 `data-standard` feature 和一级菜单，下设业务术语、主数据、参考数据、数据元标准和指标字典五个二级能力，使用 `/data-standard/*` 独立路由。数据标准域权威维护本体模型和语义层指标模型，提供企业候选归并、AI 辅助、标准落标自动稽核、跨部门指标一致性比对、整改闭环和简单版本追溯。

原 `/data-governance/standards`、旧菜单 key 和旧标准事实源删除，不提供兼容入口。数据标准不作为 `data-asset` 的资产类型，本期不建设标准资产目录发布、外部申请、授权、下发或流通流程。量化看板通过稳定引用消费数据标准来源事实并维护目标、观测、快照、趋势和改进事项。

## 后果 · Consequences

- `specs/features/data-standard/` 是后续实现的权威规格，不是历史归档。
- 目标新增 `src/features/data-standard/`、五个二级路由和 `data-agent.data-standard` SQLite mock 状态。
- 数据治理只保留元数据、血缘和质量，并引用标准 ID、版本和稽核摘要。
- 数据资产运营保留非标准资产的目录与流通，不纳管数据标准类型。
- 已存在的标准资产化代码不代表当前产品目标，应在后续代码实现阶段按 tasks 删除；本轮只完成文档，不改页面代码。

## 备选 · Alternatives Considered

- 数据标准资产化：可复用目录和流通，但无法承载五项专业工作台，且与最终“不考虑此流程”的范围决定冲突。
- 数据治理下标准页面：改动较少，但不符合数据标准一级菜单和独立 DCMM 能力域定位。
