# DCMM 第4级数据标准需求访谈与实施计划

| 元数据 | 值 |
|---|---|
| 日期 | 2026-08-13 |
| 状态 | 需求决策完成；文档固化；代码待实现 |
| 方法 | `grill-with-docs` + 官方标准核对 + 领域建模 |
| 决策记录 | ADR-0020 |

## 背景

原始需求从业务术语、主数据/参考数据、数据元和新增指标口径能力出发，希望结合 DCMM 第4级要求补齐平台。访谈进一步明确：平台只有一个产品，不存在“海盒”；“数据标准”应成为独立一级菜单；标准原文“指标数据”在产品中命名为“指标字典”；“数据元”在产品中命名为“数据元标准”。

## 标准核对结论

依据 GB/T 36073—2025 第 10 章，数据标准包含业务术语、主数据、参考数据、数据元和指标数据五项能力。企业级目录、词典、制度、发布和检查主要构成组织级基线；第4级重点是量化管理、持续优化、AI 提效和国家/行业标准参与证据。因此，本方案不把新建页面直接等同于达到 DCMM 第4级，也不生成认证结论。

## 已确认产品决策

1. 数据标准是独立一级产品域，不属于数据治理二级页面。
2. 五个二级菜单和路由固定为：业务术语、主数据、参考数据、数据元标准、指标字典。
3. 数据标准域权威维护本体模型和语义层指标模型。
4. 发布术语必须绑定唯一有效本体概念；同义词共享概念身份。
5. 指标标准发布与自动计算启用分离；后者还需要可执行语义模型和物理血缘。
6. 企业稳定指标 ID 是跨部门一致性比对的分组身份；AI 负责候选分组与差异分析，正式合并、拆分和口径变更需要人工批准。
7. 标准落标只以明确的应落标对象为分母；结果为通过、失败、未知和不适用。
8. 三项核心 KPI 保持为关键标准落标率、业务术语覆盖率和指标口径一致率，并增加五项能力诊断指标。
9. 主数据、参考数据和数据元标准都在同一平台提供完整 SQLite mock 工作台。
10. AI 自动化必须保存模型/策略版本、证据、置信度、依据摘要和复核结果；低置信度进入待复核，准确率破线暂停自动化。
11. 已发布标准不可覆盖，只提供简单的版本列表、差异、变更人、时间、原因和引用追溯。
12. 原 `/data-governance/standards` 和旧菜单 key 删除，不提供兼容路由。
13. 数据标准资产化、目录发布、外部申请、授权和下发不在当前范围。
14. 本轮只完成文档，不实现页面代码。

## 目标产品结构

| 二级能力 | 路由 | 主要交付 |
|---|---|---|
| 业务术语 | `/data-standard/business-terms` | 企业术语库、本体图、概念绑定、引用与审批 |
| 主数据 | `/data-standard/master-data` | 实体标准、来源匹配、权威记录、质量与分发 |
| 参考数据 | `/data-standard/reference-data` | 目录、代码值版本、映射矩阵、差异与同步 |
| 数据元标准 | `/data-standard/data-element-standards` | 数据元目录、字段映射、AI 落标与符合性 |
| 指标字典 | `/data-standard/metric-dictionary` | 指标体系、口径、语义模型、血缘和一致性比对 |

## 实施阶段

### 阶段一：产品基座

- 创建独立 feature、五个路由、菜单稳定 key 和 `data-agent.data-standard` 状态。
- 删除旧数据治理标准入口和事实源。
- 建立候选导入、企业稳定 ID、标准版本和项目版本映射。

### 阶段二：五项工作台

- 按 design.md 的差异化页面信息架构实现五个工作台。
- 主数据、参考数据和语义层均为本地 SQLite mock，不连接真实引擎。
- 五个工作台分别覆盖加载、空态、失败、运行中、成功和停止状态。

### 阶段三：审批与自动化

- 建立维护人、数据管家和标准负责人的责任链。
- 建立稽核批次、整改、复检、例外和证据闭环。
- 建立 AI 依据摘要、抽样准确率、自动化暂停和恢复。

### 阶段四：量化闭环

- 数据标准域生成指标来源事实，量化看板维护正式目标、观测、快照、趋势和改进事项。
- 历史快照冻结当期目标版本、标准版本和证据。
- 五项能力分别提供量化诊断，不用单一综合分数代替差距分析。

## 验证门槛

- 五个菜单、路由、页面任务和状态事实一致。
- 业务术语、本体、数据元、指标语义关系有稳定 ID 和版本引用。
- 项目定义导入不会直接发布或覆盖；迁移后必须按指定企业版本稽核。
- AI 不自我批准正式标准，关键冲突不自动合并，低置信度不伪装为成功。
- 稽核批次、整改证据和历史指标不可被后续版本覆盖。
- 产品文案不宣称认证通过或软件自动达到 DCMM 第4级。

## 明确不做

- 数据标准资产发布、外部申请、授权、下发和流通。
- 旧路由兼容、复杂版本状态机、主次版本分类和迁移宽限期。
- 真实 MDM、参考数据服务、扫描器、语义执行引擎、AI 服务和生产写回。
- 细粒度权限系统、真实审批引擎和 DCMM 认证评分。
