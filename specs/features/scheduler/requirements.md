# Scheduler · Requirements

## 目标用户 · Personas

| 角色 | 场景 | 期望产出 |
|---|---|---|
| 数据工程师 | 编排集成、开发、处理和质量节点 | 可复用、可运行的 DAG 任务 |
| 数据服务开发者 | 将数据服务加入统一调度 | 可发布、可监控的服务任务 |
| 运维人员 | 观察任务状态和执行日志 | 快速定位、重跑和停止异常任务 |

## 用户故事 · User Stories

- **US-01** 作为工程师，我希望通过画布拖拽节点创建任务，以便直观编排数据处理流程。
- **US-02** 作为工程师，我希望查看和编辑节点配置、连线和结果，以便在发布前验证任务。
- **US-03** 作为运维人员，我希望查看任务状态、进度、耗时和日志，并执行运行/停止/重跑，以便保障任务稳定运行。

## 验收标准 · Acceptance Criteria

- **AC-01** 画布应支持缩放、平移、节点拖拽、连线、节点新增、编辑、删除和选中详情。
- **AC-02** 节点类型至少覆盖数据集成、数据开发、数据处理、数据质量校验和数据服务，并为不同类型展示对应配置。
- **AC-03** 节点或任务运行后应能查看结果、状态、日志和错误信息；前端 mock 可以使用确定性 fixture。
- **AC-04** 任务监控应支持筛选、创建、编辑、删除、运行和执行日志查看。
- **AC-05** 任务模型应保留版本、负责人、触发策略、输入/输出、血缘关联和运行记录。
- **AC-06** 生产执行、权限、资源配额和重试语义必须由调度后端定义，前端不得伪造执行成功作为真实结果。

## 范围 · Scope

- 任务画布和节点配置
- 数据集成/开发/处理/质量校验/服务任务类型的统一编排
- 任务列表、运行状态、执行日志和基本运行控制

## 非目标 · Out of Scope

- 真实 DAG 调度器、分布式执行器、资源队列和容错内核
- 复杂依赖表达式、跨集群编排和生产级告警策略
