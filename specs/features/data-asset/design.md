# Data Asset · 数据资产管理设计

> 状态：设计访谈草案。本文只记录已确认的设计决策，访谈结束并确认共同理解后再进入实现。

## 设计依据

- 功能范围以 [`requirements.md`](./requirements.md) 中的数据资产目录、权属登记、价值评估、资产运营和资产使用审计五项需求为准。
- 参考 GB/T 36073—2025 DCMM 4 级要求强化量化指标、趋势监测、过程留痕、证据追溯和持续改进，不以标准为由扩展本期功能范围。
- 当前仓库仍采用 SQLite 持久化 mock，不接入真实扫描器、权限中心、API 网关或下载服务。

## 简化边界

本期以可演示、可持久化、可追溯的基础闭环为目标。使用固定页面、固定状态、固定表单、固定审批模板和固定估值公式；不建设通用工作流设计器、任意公式编辑器、复杂权属冲突引擎或通用影响分析引擎。已确认的到期、敏感字段和发布门槛等联动只实现为明确的固定规则。

## 量化管理

量化指标统一具备指标 ID、名称、定义、计算口径、目标值、实际值、统计周期、趋势、数据时间、异常原因和改进措施。指标结果应能回溯到扫描批次、资产、权属版本、评估记录、访问审计或整改记录等事实数据。

首期默认目标采用 [`requirements.md`](./requirements.md) 中确认的八项指标。默认值可配置，界面和报告必须注明其为组织管理目标，不标记为国标规定阈值。

### 管理报告

系统每月生成目录质量、权属管理、价值评估、资产运营和使用审计专项报告，每季度生成综合管理报告。报告由指标快照、趋势、差距原因、责任人、改进措施、截止时间和复核结果组成。

报告生成后版本冻结。底层数据修正时重新生成新版本并说明修订原因，不覆盖历史报告。当前原型只提供查看与模拟导出，不声称输出可直接用于认证的正式材料。

## 信息架构

| 页面 | 路由 | 职责 |
|---|---|---|
| 资产目录 | `/data-asset/catalog` | 扫描任务、资产目录、资产详情和资产版本 |
| 资产流通 | `/data-asset/circulation` | 直接资产的申请、审批、对接和使用证据 |
| 权属登记 | `/data-asset/ownership` | 持有权、使用权、经营权、变更审批和权属版本 |
| 价值评估 | `/data-asset/value` | 评估任务、成本法/收益法/市场法、复核、有效估值和评估报告 |
| 资产运营 | `/data-asset/service` | 数据产品、发布审批、使用授权、API/下载服务和使用统计 |
| 使用审计 | `/data-asset/audit` | 访问明细、异常分析、指标趋势和整改跟踪 |

保留现有 `/data-asset/value` 和 `/data-asset/service` URL；新增稳定路由 `/data-asset/circulation` 和菜单项“资产流通”，承载直接资产使用流程，菜单中的“数据服务”继续使用“资产运营”。

### 资产目录页面

资产目录采用“自动扫描为主、从数据源直接添加和人工补录为辅”的添加方式：

- 顶部展示资产总数、待确权数量、来源异常数量和扫描更新及时率。
- 左侧按业务域组织资产，列表支持按资产类型、来源系统和状态筛选及统一搜索。
- 页面操作包括“从数据源添加”“新建扫描任务”“人工补录”和“扫描记录”，不建设复杂批量导入中心。
- 待办区域集中展示待确权、待合并、来源异常和待退役资产。
- “从数据源添加”读取共享数据源注册表，选择后记录稳定 `dataSourceId`、脱敏摘要和来源对象定位信息；数据源类型用于给出默认资产类型，但允许管理员调整。
- “人工补录”由公共信息和类型专属信息组成，来源系统为自由填写，适用于无法自动扫描的报告、文档和模型；两种入口保存后均生成稳定资产 ID 并进入待确权。

资产详情提供“基本信息、类型信息、权属信息、版本历史、价值评估、关联产品、使用审计、变更历史”页签。目录描述、标签和负责人等人工信息变化写入变更历史；扫描发现的来源结构或定义变化生成资产版本与差异记录。

数据标准不属于本目录类型。其他资产可以只读引用独立数据标准域提供的标准 ID 和版本 ID，但不能在本 feature 发布、审批或流通标准正文。

### 资产流通页面

核心任务是让申请人、审批人和对接负责人围绕同一申请看清“目前到哪一步、为什么卡住、下一步由谁处理、留下了什么证据”。页面采用主从流程工作台，不使用通用指标卡加 CRUD 表格：

- 顶部用“申请提交 → 审批授权 → 对接配置 → 使用跟踪”流程带解释固定边界，并以视图切换聚焦申请、审批、对接和使用四类待办。
- 左侧为申请队列，按当前视图和关键字收敛；每项展示资产类型、申请方、当前状态和等待责任人。
- 中部展示选中申请的资产版本快照、用途、范围、期限、审批时间线、对接检查清单及使用记录。
- 右侧只展示当前阶段的决策信息和下一步动作，例如审批风险理由、对接负责人、失败原因或可模拟使用入口。
- 新建申请使用分步表单，先选择资产版本，再填写消费方与用途，最后确认 API、文件下载或在线查询等交付方式和期限。

该页面与“资产运营”的布局和对象不同：资产流通以直接资产申请为主对象，资产运营以数据产品、发布门槛和产品授权为主对象；两者通过稳定资产 ID 和版本快照关联，不共享可编辑申请记录。

## 多维状态模型

资产不设置混合所有流程的单一生命周期状态。资产详情并列呈现：

| 维度 | 状态 |
|---|---|
| 目录 | 正常、来源异常、待退役、已退役、已归档 |
| 权属 | 待登记、待确认、已确权、已失效 |
| 评估 | 未评估、进行中、待复核、有效、待替代、已过期 |
| 运营 | 无产品、草稿、审批中、运营中、已暂停、已下线 |

跨域风险通过状态组合和提示展示。例如“估值待替代、产品运营中”显示更新预警，但不将资产整体改成含义模糊的“处理中”。

## 资产元数据模型

目录采用公共信息与类型扩展信息组合的模型：

| 层级/类型 | 元数据 |
|---|---|
| 公共信息 | 资产 ID、名称、类型、来源系统、可选数据源 ID、来源对象 ID、业务域、描述、标签、目录状态、资产版本、更新时间 |
| 数据库表 | 数据库、Schema、表名、字段、主键、数据量、更新时间 |
| API | 协议、路径、方法、请求参数、响应结构、接口版本 |
| 报告 | 报告格式、关联数据集、更新周期、生成系统、报告版本 |
| 模型 | 模型类型、输入输出、训练数据来源、算法或框架、模型版本、效果指标 |

公共信息支撑统一目录检索和稳定身份，类型扩展信息用于扫描差异、详情展示和资产版本追踪。

数据源管理与资产目录通过共享 store 读取同一 SQLite scope `data-agent.data-source.sources`。feature 之间不直接 import；共享的数据源类型、默认 fixture 和 hook 位于 `src/stores/dataSourceRegistry.ts`。

类型体系保留现有数据表、数据集、指标、标签、数据服务、JSON、XML、日志、消息数据、文档、图片、视频、音频和知识资料，并新增“模型”。API 映射为“数据服务/API”，报告映射为“文档/报告”。数据标准不作为 `AssetType`。

### 安全分类引用

资产与字段只引用数据安全模块中当前生效的分类分级记录及其版本，不在数据资产模块复制维护安全等级。发布门槛、使用授权、API 调用和下载校验均使用该分类结果。

分类等级提高或新增敏感字段时，系统按产品和授权的数据范围执行影响分析。受影响对象进入“安全待复核”，在整改期限内允许按现有策略继续或由安全审批人主动暂停；超过期限仍未复核时自动暂停相关产品。

### 资产身份与扫描匹配

平台资产 ID 是跨版本永久身份，不使用名称或来源路径充当主标识。扫描时按以下优先级匹配：

1. 来源系统提供的稳定对象 ID。
2. 类型专属来源定位键。
3. 无法可靠匹配时创建待合并资产，由资产管理员核对。

数据库表定位键为“数据源 ID + 数据库 + Schema + 表名”，API 为“来源系统 ID + HTTP 方法 + 路径”，报告为“来源系统 ID + 报告 ID”，模型为“来源系统 ID + 模型注册 ID”。疑似重复记录不得自动合并或覆盖。

### 扫描任务

扫描任务采用“待运行 → 运行中 → 成功/部分成功/失败/已取消”状态。批次记录扫描范围、全量/增量模式、时间、发现/新增/变更/异常数量、错误摘要及执行日志。

扫描处理以批次 ID、来源对象 ID 和内容指纹保证幂等；相同内容不生成空资产版本。部分成功任务支持按失败对象重试，已成功对象不重复处理。

### 资产退出

目录资产按“正常 → 来源异常 → 待退役 → 已退役 → 已归档”退出，不执行业务硬删除。退役前必须检查并处理已发布产品、有效授权和未关闭异常；归档后保留资产版本、权属版本、评估记录、产品与授权记录及使用审计，只提供只读访问。

未关联任何后续记录的误录资产允许作废，但作废动作本身必须留痕。

## 业务角色与职责分离

| 角色 | 职责 | 分离约束 |
|---|---|---|
| 资产管理员 | 管理扫描、目录和资产状态 | 不代替权属主体确认权属 |
| 权属登记人 | 提交权属登记及变更 | 不得确认自己提交的登记 |
| 权属确认人 | 代表持有、使用或经营主体确认权属 | 与登记提交人分离 |
| 评估人员 | 执行估值并提交评估过程和依据 | 不得复核自己的评估 |
| 评估复核人 | 批准或驳回估值 | 与评估人员分离 |
| 资产运营人员 | 创建数据产品并提交发布 | 不代替安全审批人批准发布 |
| 安全审批人 | 审核发布范围和使用授权 | 与发布提交人分离 |
| 数据使用方 | 申请并使用 API 或下载服务 | 只能在有效授权范围内使用 |
| 审计人员 | 只读查看审计、异常和整改记录 | 不修改原始审计事件 |

当前原型只模拟角色、审批结果和职责分离证据，不声称实现真实 IAM 权限控制。

资产负责人是每项资产的日常管理责任人，与权属主体分离。负责人变化属于管理信息变更并单独留痕，不产生权属版本；持有权、使用权和经营权只能通过权属登记流程变更。

### 权属基础校验

权属登记仅执行必填项、起止日期和明显重复校验。明显重复指同一资产下主体、权利类型、数据范围和有效期均相同的记录。本期不实现独占权、上下级权利链或自动冲突推断，其他判断由权属确认人在审批时完成。

## 审批模板

本期采用固定流程模板并允许配置审批人，不建设通用工作流设计器：

| 业务 | 固定流程 |
|---|---|
| 权属登记 | 登记人提交 → 对应权属主体确认 |
| 价值评估 | 评估人员提交 → 评估复核人审批 |
| 产品发布 | 运营人员提交 → 资产负责人确认 → 安全审批人审核 |
| 使用授权 | 使用方提交 → 资产负责人审批；敏感数据或对外使用时追加安全审批 |
| 直接资产流通 | 使用方提交 → 资产负责人审批；敏感数据或对外使用时追加安全审批 → 对接负责人配置与联调 |

节点处理动作包括通过、驳回和退回修改。管理员可以调整节点审批人、办理时限及触发安全审批的条件，但不能取消提交人与确认/复核人的职责分离。

### 资产流通状态与持久化

流通状态保存在现有 `data-agent.data-asset` scope 的 `circulation` 分区：`applications` 保存申请及审批步骤，`integrationTasks` 保存脱敏配置和检查清单，`usageRecords` 保存模拟使用证据。状态转换固定为：

`草稿 → 待负责人审批 →（条件性）待安全审批 → 待对接 → 对接中 → 使用中`。

退回、驳回、对接失败和暂停为显式分支，不删除已有审批或对接证据。申请在创建时冻结资产版本；目录中新版本发布后，旧申请不会自动升级。

## 发布门槛

数据产品正式发布前依次校验以下条件：

1. 关联资产为“已确权”。
2. 有效经营权覆盖产品的数据范围和 API/下载交付方式。
3. 关联资产存在一份有效估值。
4. 产品服务版本信息完整。
5. 发布审批与安全审核均已通过。

任一条件不满足时只允许保存草稿和执行模拟测试，不允许产品进入“已发布”。门槛校验结果和未通过原因应保留为发布证据。

### 权属失效联动

经营权到期前 30、7、1 天生成提醒。持有权或经营权到期、撤销后，系统立即暂停其覆盖的数据产品；既有使用授权保留原状态与历史证据，但运行时校验拒绝 API 调用和文件下载。

新权属关系生效后不自动恢复产品，由资产运营人员核对主体、范围、用途和交付方式后手动恢复，并记录恢复依据。

### 数据产品与资产版本

一个数据产品可以组合多个数据资产。产品中的每个资产引用固定资产 ID、资产版本、使用范围、经营权记录和用途。已发布服务版本保存完整关联快照，不动态读取资产最新版本。

资产版本变化不会静默改变已发布产品。运营人员需要创建新服务版本、选择新资产版本并重新通过发布门槛和审批；历史审计仍关联调用时的服务版本及资产版本快照。

## 评估数据来源

每个成本法、收益法或市场法输入参数均关联一条可追溯的数据来源：

| 字段 | 含义 |
|---|---|
| 来源类型 | 财务成本台账、业务收益预测、市场可比案例或人工补充材料 |
| 来源名称/期间 | 材料名称及其覆盖的业务或会计期间 |
| 提供与采集 | 数据提供方、采集时间 |
| 证据引用 | 可供复核的证据编号或脱敏引用 |
| 质量与合规 | 数据质量说明及合规说明 |
| 数值调整 | 原始值、调整后值及调整原因 |

当前 SQLite 原型只保存脱敏 mock 数值和证据编号，不保存真实财务凭证或敏感材料。

### 估值计算模板

首期采用固定公式模板和可配置参数，不提供任意公式或脚本编辑：

| 方法 | 计算模板 | 关键参数 |
|---|---|---|
| 成本法 | 重置成本 - 功能性贬值 - 经济性贬值，再应用质量与合规调整系数 | 成本项、贬值额、质量系数、合规系数 |
| 收益法 | 预测期增量净收益及终值的折现现值之和 | 预测年限、逐年净收益、折现率、终值 |
| 市场法 | 多个可比价格经差异调整后的加权结果 | 可比案例、规模/质量/权利范围/时效/市场调整、权重 |

计算过程展示参数单位、来源、公式、中间值和结果。结果字段只读，任何变化必须来自有证据和调整理由的参数变更。

### 估值有效期与重评

有效估值默认有效 12 个月，支持按评估调整，到期前 30、7、1 天提醒。以下事件提前触发重评：质量或合规状态恶化、成本或收益预测变化超过 20%、关键市场可比案例失效。

触发重评后，原估值转为“待替代”，不得用于新的产品发布。存量已发布产品先进入“估值待更新”预警，不立即下线；超过可配置整改期限仍未形成新有效估值时自动暂停。

### 评估基准快照

评估记录固定资产 ID、资产版本、评估基准日、有效期、权属版本和安全分类版本。原评估快照不可随目录、权属或安全分类变化而更新。资产新版本通过差异影响判断是否触发重评，原报告始终可追溯到当时的管理状态。

## 下载交付控制

下载任务在使用授权批准后生成，并绑定服务版本、资产版本和授权记录。系统在每次文件生成或下载前校验有效期、剩余次数、数据范围、文件格式、脱敏策略、授权状态和产品状态。

文件过期、授权撤销、产品暂停或下线后，下载任务立即失效。每次生成与下载尝试均写入资产使用审计，包括成功、失败和拒绝。当前原型只模拟文件生成与下载结果，不创建包含真实业务数据的文件。

## API 授权控制

API 调用关联使用方、使用授权、服务版本和资产版本。每次模拟调用前校验：

1. 数据产品处于已发布状态。
2. 使用授权已生效且未过期或撤销。
3. 本次声明的使用目的与授权目的一致。
4. 请求字段、行范围或业务区域没有超出授权范围。
5. 调用配额仍有余量。

任一校验失败时拒绝整次调用并生成资产使用审计。当前原型不生成真实密钥，也不连接真实 API 网关。

### 访问目的

访问目的在使用授权审批时确定，并从统一的标准目的列表选择，同时允许填写说明。每次 API 调用、文件生成和下载自动继承授权目的，调用方可以补充本次具体场景，但不能覆盖授权目的。目的不一致视为越权访问并进入审计与异常识别。

## 异常访问闭环

访问异常按“待研判 → 已确认异常/已排除 → 整改中 → 待复核 → 已关闭”处理。异常识别规则、严重等级和阈值可配置；异常必须关联原始审计记录、责任人、研判依据、整改措施、截止时间和复核结果。

原始审计事件不可编辑或删除。被排除的异常仍保留记录与排除依据，但不进入待整改数量；已确认异常只有通过复核才能关闭。

### 访问来源结构

使用审计以结构化字段记录使用方主体、来源应用 ID 与脱敏名称、API/下载/在线查询/预览渠道、脱敏 IP 或网络区域、用户或服务账号 ID 及请求追踪 ID。身份标识只用于关联，不保存密码、令牌或其他真实凭证。

### 审计保留与清理

资产使用审计默认保留 3 年，并允许组织按资产安全等级、产品类型及监管要求配置更长周期；界面必须注明这是组织策略而非国标统一期限。

到期事件先归档。存在未关闭异常、调查或证据保全标记时冻结清理；满足保留策略后执行清理时，保留清理规则、执行人、时间、记录数量、结果和汇总统计。当前原型只模拟归档、冻结和清理结果，不对 SQLite 中的审计记录执行真实物理删除。
