# Data Asset · 数据资产管理需求

> 状态：需求访谈草案。本文只记录已明确或已确认的产品需求，未确认的设计决策在访谈完成后补充。

## 建设目标

建立企业级数据资产目录，实现数据资产从确权到运营的全生命周期管理。功能范围以本需求为准，并参考 GB/T 36073—2025 DCMM 4 级要求强化量化管理、过程留痕、证据追溯和持续改进能力。

## 简化原则

本期实现资产目录、权属、估值、资产流通、产品运营和使用审计的基础业务闭环，采用固定状态、固定表单和固定审批模板，不建设通用工作流、任意公式、复杂权属冲突或通用影响分析引擎。跨模块联动以少量已确认的固定规则和 SQLite 持久化 mock 状态反馈实现。

## 核心功能

资产详情并列展示目录、权属、评估和运营四组独立状态，不以一个总状态混合不同管理流程：

| 状态维度 | 状态值 |
|---|---|
| 目录 | 正常、来源异常、待退役、已退役、已归档 |
| 权属 | 待登记、待确认、已确权、已失效 |
| 评估 | 未评估、进行中、待复核、有效、待替代、已过期 |
| 运营 | 无产品、草稿、审批中、运营中、已暂停、已下线 |

例如，资产可以同时处于“目录正常、已确权、估值待替代、产品运营中”，以便分别定位风险和统计指标。

## DCMM 4 量化目标

以下数值是本产品为落实 DCMM 4 量化管理要求设置的首期默认目标，可由管理员调整，并非 GB/T 36073—2025 规定的固定认证阈值：

| 指标 | 默认目标 | 计算方向 |
|---|---:|---|
| 目录编目完整率 | ≥ 98% | 已编目且必填信息完整的资产数 / 应编目资产数 |
| 元数据准确率 | ≥ 97% | 抽检或校验通过的元数据项 / 已检查元数据项 |
| 扫描更新及时率 | ≥ 95% | 在规定时间内完成同步更新的变更数 / 已发现变更数 |
| 权属登记完整率 | ≥ 98% | 权属必填信息完整的已登记资产数 / 应登记资产数 |
| 权属变更按期完成率 | ≥ 95% | 在规定时限内完成的权属变更数 / 到期权属变更数 |
| 价值评估按期复核率 | ≥ 95% | 在规定时限内完成复核的评估数 / 到期应复核评估数 |
| 运营访问审计覆盖率 | = 100% | 已生成审计记录的数据访问数 / 全部数据访问数 |
| 异常访问闭环率 | ≥ 95% | 已完成整改并关闭的异常访问数 / 到期异常访问数 |

每项指标应支持目标值、实际值、统计周期、趋势、异常原因和改进措施，并能追溯计算所使用的业务记录。

- 每月生成目录质量、权属管理、价值评估、资产运营和使用审计五类专项报告，每季度生成数据资产综合管理报告。
- 报告记录统计周期、指标目标与实际值、趋势、未达标原因、责任人、改进措施、截止时间和复核结果。
- 报告生成后冻结版本；源数据修正时生成新版本，不覆盖旧报告。
- 当前原型支持页面查看和模拟导出，不将 mock 报告标记为具有认证效力的正式材料。

#### 量化改进场景

月度目录质量报告显示扫描更新及时率为 92%，低于 95% 目标。负责人登记“缩短报告系统扫描周期”的改进措施和完成期限；下月报告继续展示整改状态以及指标变化。

### FR-01 数据资产目录

- 自动扫描并编目数据库表、API、报告和模型等数据资产；数据标准由独立产品域管理，不进入本目录。
- 资产添加采用“自动扫描为主、从数据源直接添加和人工补录为辅”，不建设复杂批量导入中心。
- “从数据源添加”直接读取数据集成模块已登记的数据源，保存数据源 ID、来源对象 ID 或类型定位信息；“人工补录”用于无法自动扫描的报告、文档、模型等资产，来源系统允许人工填写。
- 从数据源添加或人工补录时选择资产类型，填写公共信息和对应类型专属信息；保存后生成稳定资产 ID 并进入“待确权”。
- 保留现有数据表、数据集、指标、标签、数据服务、JSON、XML、日志、消息数据、文档、图片、视频、音频和知识资料类型，并新增“模型”类型。
- 扫描到的 API 归入“数据服务”类型、子类型“API”；报告归入“文档”类型、子类型“报告”；数据库表使用“数据表”类型；模型使用新增的“模型”类型。
- 所有资产统一记录资产 ID、名称、类型、来源系统、可选数据源 ID、来源对象 ID、业务域、描述、标签、目录状态、资产版本和更新时间。
- 每项资产设置一名资产负责人，负责目录信息、变更确认和使用申请审批；资产负责人不代表数据持有、使用或经营主体。
- 负责人变更记录操作人、原因和时间，但不生成权属版本。
- 平台为每项资产生成在名称、位置和版本变化时保持不变的永久资产 ID。
- 扫描匹配优先使用来源系统的稳定对象 ID；缺失时使用类型专属来源定位键：数据库表使用“数据源 ID + 数据库 + Schema + 表名”，API 使用“来源系统 ID + HTTP 方法 + 路径”，报告使用“来源系统 ID + 报告 ID”，模型使用“来源系统 ID + 模型注册 ID”。
- 来源对象 ID 不变但名称或位置变化时生成新的资产版本；无法可靠判断是否为同一对象时创建待合并资产，由资产管理员核对，不自动合并或覆盖。
- 数据库表记录数据库、Schema、表名、字段、主键、数据量和更新时间。
- API 记录协议、路径、方法、请求参数、响应结构和接口版本。
- 报告记录报告格式、关联数据集、更新周期、生成系统和报告版本。
- 模型记录模型类型、输入输出、训练数据来源、算法或框架、模型版本和效果指标。
- 资产及字段通过稳定资产 ID 引用数据安全模块中当前生效的分类分级记录，不在资产模块重复维护另一套安全分类。
- 安全等级提高或新增敏感字段时，按数据产品和授权的数据范围执行影响分析；受影响对象进入“安全待复核”，超过整改期限未完成复核时暂停相关产品。
- 资产扫描和“从数据源添加”复用数据集成模块中已登记的数据源 ID，不在资产模块重复保存密码或连接配置；数据源被修改后，资产仍通过稳定 ID 保留来源引用。
- 支持手动扫描和周期扫描，默认采用增量扫描并允许执行全量扫描。
- 扫描任务状态为“待运行、运行中、成功、部分成功、失败、已取消”。
- 每个扫描批次记录扫描范围、模式、开始与结束时间、发现/新增/变更/异常数量、错误摘要和执行日志。
- 同一批次重复执行不得重复创建资产或资产版本；部分成功任务允许只重试失败对象。
- 扫描发现的资产自动进入目录，初始标记为“待确权”，不设置目录外候选资产池。
- 扫描发现新对象时创建待确权资产；来源结构或定义变化时生成新的资产版本及差异记录。
- 目录描述、标签、负责人等人工管理信息变化只进入变更历史，不区分普通或重大变更等级。
- 暂时无法扫描到已有对象时标记为“来源异常/待确认”，不得自动删除历史资产。
- 目录资产退出状态为“正常、来源异常、待退役、已退役、已归档”，不提供业务硬删除。
- 退役前检查已发布产品、有效授权和未关闭异常；完成产品下线及授权处理后才允许退役和归档。
- 已退役或归档资产仍可只读查看全部历史证据，但不得新增授权或发布数据产品。
- 未关联后续记录的误录资产可以作废，但必须保留作废人、原因和时间。
- 保留扫描批次、资产来源、原始元数据和变更差异。
- 目录管理应提供完整率、准确率、更新及时率和扫描异常等量化指标。
- 自动扫描和 DCMM 4 目录指标覆盖管理员配置的扫描范围，不限定为数据库表、API、报告和模型四类。
- 资产详情提供基本信息、类型信息、权属信息、版本历史、价值评估、关联产品、使用审计和变更历史。
- 目录页提供业务域/类型/来源筛选、统一搜索、扫描任务、人工添加、扫描记录，以及待确权、待合并、来源异常和待退役待办。

#### 场景 A：增量扫描发现新增、变更与异常

夜间扫描发现新增 `orders_2026` 表时，系统自动编入目录并标记为待确权；发现 `customer` 表新增手机号字段时生成资产新版本和字段差异；某张表因来源暂时不可用而未被扫描到时只标记来源异常并告警，不删除已有资产。

扫描 CRM 数据库时生成带字段结构的数据库表资产；扫描 BI 系统时生成带更新周期和关联数据集的报告资产。两类对象使用同一个资产 ID 体系和目录搜索入口，详情页按资产类型展示专属信息。

`customer` 表新增手机号字段并被数据安全模块标记为敏感时，使用该字段的下载产品进入安全待复核；不包含该字段的汇总 API 不受影响。当前原型通过共享资产 ID 和 mock 分类记录模拟联动。

`customer_info` 重命名为 `customer_profile` 时，如果扫描器仍获取到相同来源对象 ID，系统沿用资产 ID 并生成新资产版本；如果来源系统没有稳定对象 ID，系统创建待合并资产，避免错误覆盖旧资产。

张明是“客户标签库”的资产负责人，负责日常维护和授权审批；数据中心才是持有主体。张明调岗只变更资产负责人并保留变更记录，不改变数据中心的持有权。

来源数据库中的旧表已经正式删除，但仍有关联的下载产品和两条有效授权时，平台将资产标记为待退役并阻止直接归档；产品下线且授权撤销或到期后，才能完成退役并转为只读归档。

一次扫描发现 200 个对象，其中 190 个成功、10 个因来源 API 限流失败。任务标记为部分成功，190 个结果正常入目录；管理员只重试失败对象，不重新创建前 190 个资产或版本。

无法自动扫描的报告由资产管理员人工补录。管理员选择“文档/报告”，填写来源系统、业务域、负责人、报告格式、更新周期和关联数据集；保存后系统生成资产 ID，并将其标记为待确权。

### FR-02 权属登记

- 记录数据持有权、使用权和经营权及其主体、范围和有效期。
- 一个资产可以同时登记多个持有、使用和经营主体，每条权属关系分别设置数据范围、用途、有效期、登记依据和状态。
- 经营权到期前 30、7、1 天提醒；到期或持有权/经营权被撤销时，立即暂停其覆盖的数据产品。
- 权属失效导致产品暂停时保留原使用授权记录，但禁止实际调用和下载；新权属生效后由运营人员核对范围并手动恢复产品。
- 分别维护资产版本、权属版本和服务版本，三类版本关联同一个稳定资产 ID。
- 权属版本经审批生效后不可覆盖，应保留变更前后内容、变更原因、申请人、审批人和生效时间。
- 权属登记采用“登记人提交 → 对应权属主体确认”的固定流程模板。
- 权属登记只校验必填信息、开始时间早于结束时间，以及同一主体/权利类型/数据范围/有效期的明显重复；其他权属判断由权属确认人在审批时负责。
- 提供权属完整率、变更及时率、风险记录和定期评价等量化信息。

本期不设计独占权、上下级权利链或自动权属冲突推断。

#### 场景 B：多主体权属登记

“客户标签库”由数据中心持有，市场部和风控部分别拥有不同字段范围的使用权，数据运营部拥有内部经营权，合作机构只拥有特定区域和期限的经营权。新增、调整、到期或撤销其中任何一条权属关系时，系统均生成新的权属版本并保留原记录。

某合作机构的华东区域经营权在 8 月 31 日到期。平台提前 30、7、1 天提醒；9 月 1 日仍未续期时，涉及华东区域的 API 自动暂停，相关授权继续可查但调用被拒绝。续期完成后由运营人员核对新经营权范围并手动恢复产品。

### FR-03 价值评估

- 支持成本法、收益法和市场法。
- 成本法采用“重置成本 - 功能性贬值 - 经济性贬值”，并应用质量与合规调整系数。
- 收益法将预测期增量净收益及终值按折现率计算现值，支持配置预测年限和终值。
- 市场法选择多个可比数据产品价格，按规模、质量、权利范围、时效和市场条件调整后加权。
- 首期使用固定计算模板和可配置参数，不建设任意公式编辑器；系统展示公式、参数单位、来源、中间值和结果，评估人员不得直接覆盖计算结果。
- 一份评估可以采用一种或多种方法，每种方法独立记录输入参数、计算公式、计算结果和数据来源。
- 每份评估绑定稳定资产 ID、采用的资产版本、评估基准日、有效期，以及当时生效的权属版本和安全分类版本。
- 后续资产版本变化不得修改原评估快照；系统根据变更影响判断是否触发重新评估。
- 每个评估输入记录来源类型、来源名称、所属期间、数据提供方、采集时间、证据引用、数据质量与合规说明。
- 数值经过调整时同时保留原始值、调整后值和调整原因。
- 多方法评估由评估人员设置权重形成最终估值，并记录权重依据和调整说明。
- 评估状态为“草稿、计算中、待复核、已生效、已驳回、已过期、已被替代”。
- 评估结果经复核批准后才能成为有效估值；资产结构、质量或合规状态发生重大变化时提示重新评估。
- 价值评估采用“评估人员提交 → 评估复核人审批”的固定流程模板。
- 有效估值默认有效期为 12 个月，可在评估时调整；到期前 30、7、1 天提醒。
- 质量或合规状态恶化、成本变化超过 20%、收益预测变化超过 20% 或关键市场可比案例失效时，提前触发重新评估。
- 触发重评后原估值标记为“待替代”，不得用于新的产品发布；关联已发布产品进入“估值待更新”预警，超过整改期限仍未完成时自动暂停。
- 评估过程应版本化并可追溯，提供评估报告和持续改进记录。

#### 场景 C：多方法估值与复核

评估人员对某资产分别得到成本法 120 万元、收益法 200 万元和市场法 160 万元的结果，按 30%、50%、20% 加权形成 172 万元估值，并提交数据来源、权重依据和调整说明。复核人批准后该版本成为有效估值；后续资产结构、质量或合规状态发生重大变化时，系统提示重新评估并保留原评估版本。

收益法使用未来三年收入预测时，记录预测的业务提供部门、覆盖期间和预测依据。评估人员将收入预测下调 10% 时，系统同时保留原值、调整后值和调整理由。当前原型只保存脱敏 mock 数值与证据编号，不保存真实财务凭证。

某资产估值尚有三个月有效期，但收益预测下降 25%，系统提前触发重新评估并将原估值标记为待替代。原估值仍可查看，但不能支撑新的产品发布；已有产品进入估值待更新预警，超过整改期限仍未完成时自动暂停。

收益法录入未来三年增量净收益和 10% 折现率后，系统逐年展示折现计算结果。评估人员不能直接修改计算结果，只能调整具有来源、证据和调整理由的输入参数。

资产 V3 基于 6 月 30 日状态完成估值。7 月新增普通描述字段形成 V4 时原估值可以继续有效；V4 新增大量核心数据或敏感字段时触发重新评估。原评估报告始终显示其资产版本基准为 V3。

### FR-04 资产运营

- 支持数据产品的发布、审批、授权和使用统计。
- 一个数据产品可关联一个或多个数据资产；每个关联项记录资产 ID、资产版本、使用范围、经营权记录及其在产品中的用途。
- 已发布服务版本固定关联资产快照，不随目录最新版本自动变化；变更资产版本时创建新的服务版本并重新发布审批。
- 对外提供 API 或下载服务。
- 每次 API 调用关联使用方、使用授权、服务版本和资产版本；调用前校验产品状态、授权有效期、使用目的、字段/数据范围和配额。
- API 授权范围可细化为字段、行范围或业务区域；超范围、过期、超配额或产品暂停时拒绝调用并生成审计记录。
- 下载授权通过后生成一次性或限次下载任务，任务关联服务版本、资产版本和授权记录。
- 下载任务可配置有效期、最大下载次数、数据范围、文件格式和脱敏策略。
- 文件过期、授权撤销、产品暂停或产品下线后禁止继续下载；文件生成和每次下载尝试都进入使用审计。
- 发布审批与使用授权是两个独立但关联的流程：发布审批决定产品能否上架，使用授权决定申请方的用途、数据范围、交付方式、有效期和配额。
- 产品发布采用“运营人员提交 → 资产负责人确认 → 安全审批人审核”的固定流程模板。
- 使用授权采用“使用方提交 → 资产负责人审批”；涉及敏感数据或对外使用时追加安全审批。
- 使用授权审批时必须选择标准目的并填写说明；API 调用和下载自动继承授权目的，调用方只能补充具体场景，不能改写或扩大目的。
- 本次声明目的与授权目的不一致时拒绝访问并记录异常。
- 审批节点支持通过、驳回和退回修改，并记录意见、处理人和时间；管理员可以配置审批人、办理时限和安全审批条件，但不能取消核心职责分离。
- 正式发布前必须同时满足：关联资产已确权、有效经营权覆盖当前数据范围和交付方式、存在有效估值、产品服务版本完整、发布审批与安全审核通过。
- 未满足发布条件时允许保存草稿和模拟测试，但不得进入“已发布”状态。
- 产品状态为“草稿、待审批、已发布、已驳回、已暂停、已下线”；授权状态为“待审批、已授权、已拒绝、已过期、已撤销”。
- 使用统计统一从资产使用审计记录汇总，不维护独立的手工调用计数。
- API 统计包括总调用量、成功量、失败量、拒绝量、超时量、成功率和平均响应时间。
- 下载统计包括申请量、审批通过量、文件生成量、成功下载量和失败量。
- 通用统计包括独立使用方数量、使用目的分布，以及按资产、数据产品、部门和日/周/月的趋势。
- 提供运营目标、量化指标、效益评价和全过程追溯信息。

#### 场景 D：发布下载型数据产品

运营人员将“区域销售月报”制作成 Excel 下载产品，配置关联资产、服务版本、文件格式、更新周期和适用对象后提交发布。资产负责人确认数据内容和权属，安全人员检查敏感字段与下载范围；审批通过后产品上架，驳回时记录原因。

“区域销售月报”权属和服务版本完整但估值已经过期时，运营人员仍可编辑草稿或执行模拟测试，系统在正式发布前提示重新评估并阻止发布。

“企业风险画像 API”同时使用企业基本信息表、司法风险报告和风险评分模型。模型升级后，运营人员创建新的服务版本并重新进行发布审批；旧版 API 的历史调用仍可追溯到原模型版本。

#### 场景 E：申请使用 API

风控系统申请调用“企业风险评分 API”，申报贷款风险审核用途、使用系统、有效期、字段范围和每日调用配额。审批通过后形成限期授权；超出配额、字段范围或有效期的调用被拒绝并记录审计事件。

风控部门获准查询客户 ID、风险等级和所在省份，但无权读取手机号。请求中包含手机号字段时，整次调用被拒绝并记录“字段超出授权范围”。当前原型只模拟鉴权和调用结果，不生成真实密钥，也不调用真实 API 网关。

普通内部统计 API 的使用申请由资产负责人审批即可；申请包含敏感字段或申请方是外部合作机构时，资产负责人通过后还必须由安全审批人批准。

某授权目的为“贷款风险审核”，调用方本次声明用于“营销推荐”时，即使字段范围和配额符合，系统仍拒绝调用并记录“目的不一致”。

#### 场景 F：申请下载数据

业务分析人员申请下载“客户经营分析报告”，填写分析目的、使用期限和数据时间范围。审批人可以调整授权范围；审批通过后生成限时下载任务，并记录下载人、来源、目的、文件版本和下载结果。

分析人员获准下载华东区 2026 年第二季度销售数据，授权 48 小时内最多下载两次。第三次下载或跨区域请求会被拒绝并记录原因。当前原型只模拟文件生成及下载结果，不生成包含真实业务数据的文件。

#### 场景 G：暂停产品或撤销授权

系统发现申请方出现大量失败调用时，运营人员可以暂停整个数据产品，也可以仅撤销异常申请方的授权。暂停、恢复、撤销及其原因均进入变更历史和审计记录。

### FR-04A 资产流通申请

- 为数据表、数据集、文档和模型等目录资产提供直接流通入口，补足“不先包装成数据产品也需要受控使用”的场景；已发布数据产品仍沿用 FR-04 的产品使用授权。
- 一张资产流通申请固定关联一个资产 ID 和申请时的资产版本，并记录申请人、申请组织、内部/外部主体、消费系统、使用目的、用途说明、申请范围、交付方式、有效期和提交时间。
- 流程采用“提交申请 → 资产负责人审批 → 条件性安全审批 → 对接配置与联调 → 使用跟踪”的固定模板，不建设通用工作流设计器。
- 资产负责人审批所有申请；涉及敏感资产或外部主体时追加安全审批。审批支持通过、驳回和退回修改，并记录处理人、意见和时间。
- 审批通过后生成资产对接任务。对接任务按 API、文件下载或在线查询显示不同的脱敏配置，记录负责人、完成期限、检查清单、联调结果和完成时间。
- 对接完成后申请进入“使用中”，页面可模拟一次使用并生成用途、消费系统、资产版本、结果和证据编号；当前原型不调用真实 API、不生成真实文件，也不签发真实凭证。
- 申请、审批、对接和使用不是四套独立业务数据，而是同一申请记录及其审批步骤、对接任务和使用记录的不同视图。
- 流通申请状态为“草稿、待负责人审批、待安全审批、待对接、对接中、使用中、已退回、已驳回、对接失败、已暂停”。

#### 场景 K：敏感数据资产分级审批与对接

外部合作机构申请使用客户标签库时，资产负责人先确认用途和字段范围，安全审批人再确认脱敏与期限。审批通过后生成 API 对接任务；联调完成前不得进入“使用中”，失败结果保留原因并允许重新处理。

#### 场景 H：审计事件形成使用统计

某 API 在一天内产生 1,000 条访问审计，其中 920 次成功、40 次失败、30 次被拒绝、10 次超时。运营统计直接汇总这些审计记录，被拒绝的调用计入拒绝量但不计入成功使用量；指标超过预警阈值时记录异常及后续改进措施。

### FR-05 资产使用审计

- 记录每次数据访问的来源、目的和结果。
- 访问来源结构化记录使用方主体、来源系统、访问渠道、脱敏来源位置、用户或服务账号 ID 及请求追踪 ID。
- 使用方主体可为人员、部门、内部系统或外部机构；来源系统记录应用 ID 和脱敏应用名称，访问渠道区分 API、下载、在线查询和预览。
- 审计结果保存成功、失败、拒绝或超时状态，以及状态码、脱敏错误原因、返回记录数或文件大小、响应时间、追踪 ID、访问时间和关联授权。
- 审计记录不得保存 API 原始响应、下载文件内容、密码、令牌或真实敏感数据。
- API 的每次成功、失败、拒绝或超时调用均生成审计记录。
- 文件生成和下载、在线查询及数据预览在实际读取数据时生成审计记录。
- 搜索目录、查看资产详情和查看审批单不属于数据访问，记录为普通操作日志而非资产使用审计。
- 结合 DCMM 4 级要求提供审计覆盖率、异常访问率、整改状态和趋势分析。
- 通过超配额、连续失败、越权字段和异常下载频率等规则识别访问异常。
- 异常状态为“待研判、已确认异常、已排除、整改中、待复核、已关闭”。
- 每条异常关联原始审计记录、责任人、严重等级、研判结论、整改措施、截止时间和复核结果；原始审计记录不得修改。
- 审计记录默认保留 3 年，可按资产安全等级、产品类型和监管要求配置更长周期；该默认值是组织策略，不是国标统一期限。
- 保留期内不得修改或业务删除原始审计事件。到期记录先归档；存在未关闭异常、调查或证据保全要求时禁止清理。
- 审计清理必须保留执行人、规则、时间、数量和结果等操作证据及汇总统计。

#### 场景 I：区分目录浏览和数据访问

用户查看“客户经营分析报告”的目录介绍时只记录普通操作日志；用户点击预览并实际读取报告数据时生成资产使用审计。API 调用或下载即使失败、被拒绝或超时，也要保留访问尝试及其结果。

#### 场景 J：最小必要审计结果

一次客户数据 API 调用成功返回 128 条记录时，审计记录保存“成功、128 条、耗时 230ms、追踪 ID 和关联授权”，但不复制保存这 128 条客户数据。失败时只保存状态码和脱敏后的错误原因，不记录请求令牌或敏感参数值。

外部合作机构的结算系统通过 API 查询数据时，访问来源显示为“合作机构 A / 结算系统 / API / 外联网区域 / 服务账号 svc-***”，而不是只记录 IP 地址；系统不保存真实账号凭证。

#### 场景 K：异常访问整改闭环

某部门一小时内连续发生 50 次越权字段请求，系统生成高风险异常。审计人员确认后指派整改，运营人员撤销相关授权；复核人验证风险已消除后关闭异常。若判定为合法压测，则记录判断依据并标记“已排除”，但仍保留异常和原始审计记录。

某访问事件已满三年但仍关联未关闭的安全调查时，系统阻止清理。调查关闭且记录满足组织保留策略后，才允许归档或清理，并保留本次清理操作的证据。
