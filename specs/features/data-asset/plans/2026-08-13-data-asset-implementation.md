# Data Asset · 实现计划（2026-08-13）

> 本文是 data-asset feature 进入实现前的计划归档，需求与设计原文见同级 `requirements.md` / `design.md`。

## 目标

按 `requirements.md`（FR-01 ~ FR-05 + 量化管理）与 `design.md`（信息架构、多维状态模型、固定审批模板、固定联动规则）实现可在本地全栈原型演示、持久化、可追溯的数据资产闭环。

## 范围

| 页面 | 路由 | 覆盖需求 |
|---|---|---|
| 资产目录 | `/data-asset/catalog` | FR-01 扫描、目录、详情、版本、退出 |
| 权属登记 | `/data-asset/ownership` | FR-02 多主体权属、变更审批、版本、到期联动 |
| 价值评估 | `/data-asset/value` | FR-03 三方法、复核、有效估值、重评、基准快照 |
| 资产运营 | `/data-asset/service` | FR-04 产品发布、授权、API/下载、统计 |
| 使用审计 | `/data-asset/audit` | FR-05 访问明细、异常闭环、整改、保留清理 |
| 量化报告 | `/data-asset/reports` | 量化管理：八项指标、月度专项/季度综合报告 |

## 架构决策

1. **状态持久化**：单一 scope `data-agent.data-asset` + `useSqliteState`，页面独占路由挂载避免并发写冲突；跨域联动（发布门槛、权属失效暂停、估值预警）在同一状态对象内直接读取。
2. **不使用 mockClient 路由**：所有操作在页面内以 `setTimeout` 模拟异步执行并写回同一状态，符合「业务页面不得直接调用外部服务」约束。
3. **固定规则**：五条发布门槛、权属到期暂停、估值待替代预警、异常识别规则均为固定实现，不做通用工作流/公式引擎。
4. **审计驱动统计**：使用统计、量化指标从审计事件与业务记录汇总，不维护独立手工计数。

## 实现顺序

spec（本文档）→ 数据层（types + 默认 mock + 纯函数业务逻辑 + store）→ 六个页面 → 路由/菜单集成 → 文档同步 → typecheck / lint / dev / db:inspect 验证。
