# Data Development · Requirements

## 1. 产品目标 · Product Goal

数据开发为数据工程师、数仓开发者、数据分析师和算法工程师提供三种互补的开发方式：

| 开发方式 | 核心对象 | 主要场景 | 最小执行单元 |
|---|---|---|---|
| 可视化 ETL | 节点与连线组成的 DAG | 标准化、可复用的数据加工流程 | 节点、下游链路、全流程 |
| SQL 开发 | SQL 脚本与参数 | 精确的数据查询、建模和批处理 | 当前语句、选中 SQL、完整脚本 |
| Notebook | 单元格组成的交互式文档 | 探索分析、实验和模型验证 | 当前单元、部分单元、全部单元 |

三种开发方式共享任务身份、版本、发布、运行、审计和血缘契约，但必须拥有独立的编辑器和交互模型，不使用同一套通用列表表单代替专业工作台。

## 2. 用户与使用边界 · Users and Boundaries

- 数据工程师使用可视化 ETL 搭建字段映射、清洗、关联、聚合和输出流程。
- SQL 开发者使用脚本编辑器完成语句编写、参数配置、校验、试运行和版本管理。
- 数据分析师和算法工程师使用 Notebook 进行有状态的交互式探索，并将可复现版本发布为任务。
- 当前仓库只提供 SQLite 持久化 mock，不连接真实数据源、ETL 执行器、SQL 引擎或 Notebook 内核。
- 不保存密码、token、私钥或完整连接串；开发对象只保存数据源、数据集、湖表和运行时的脱敏引用。

## 3. 共享需求 · Shared Requirements

### 3.1 统一身份与状态

每个开发对象必须具备 `id`、`name`、`description`、`owner`、`tags`、`status`、`currentVersion`、`publishedVersion`、`createdAt` 和 `updatedAt`。

状态必须分层管理，不得用一个 `status` 混合表达全部状态：

- 编辑状态：`clean`、`dirty`、`saving`、`save_failed`。
- 生命周期：`draft`、`ready`、`published`、`disabled`、`archived`。
- 执行状态：`queued`、`running`、`success`、`failed`、`stopped`。
- 校验状态：`unchecked`、`validating`、`valid`、`invalid`。

### 3.2 版本与发布

- 草稿可自动保存；发布时生成不可变版本。
- 调度引擎通过 `artifactType + artifactId + version` 引用开发任务，不复制可变草稿。
- 已发布版本不能原地修改，继续编辑时生成新的草稿版本。
- 发布记录必须包含版本、发布人、发布时间、变更说明和校验结果。

### 3.3 运行、日志与血缘

- 统一记录 `runId`、开发对象引用、版本、触发方式、开始/结束时间、状态、耗时、日志和结果摘要。
- ETL、SQL 和 Notebook 都应记录输入对象与输出对象引用，为调度、运维和血缘展示保留稳定 ID。
- mock 运行需覆盖排队、运行中、成功、失败、已停止、空结果和超时场景。
- 错误反馈必须能定位到 ETL 节点、SQL 行列或 Notebook 单元格。

### 3.4 持久化

- 可视化 ETL 使用 `data-agent.data-development.etl`。
- SQL 开发使用 `data-agent.data-development.sql`。
- Notebook 使用 `data-agent.data-development.notebook`。
- 状态统一通过 `useSqliteState` 写入本地 SQLite；业务 fixture 保留在本 feature，不写入通用 UI 组件。

## 4. 可视化 ETL · Visual ETL

### 4.1 任务管理

- 支持检索、创建、复制、重命名、删除和归档 ETL 任务。
- 列表展示版本、节点数、输入、输出、校验状态、发布状态、最近运行、负责人和更新时间。
- 支持从空白画布或预置模板创建任务。

### 4.2 画布编排

- 编辑器采用左侧节点库、中央画布、右侧属性面板和底部运行面板。
- 支持拖拽、连线、删除、复制、缩放、平移、自动布局和撤销重做。
- 输入节点包括数据表、文件和数据集引用。
- 转换节点至少包括字段选择、过滤、字段派生、类型转换、关联、聚合、排序、去重和合并。
- 输出节点包括湖表、数据集和临时结果引用。
- DAG 不允许形成环路；不满足输入数量要求的节点必须显示校验错误。

### 4.3 节点配置与字段映射

- 输入节点配置数据源引用、对象引用和字段 Schema。
- 转换节点配置表达式、关联条件、聚合维度等节点专属参数。
- 输出节点配置目标对象、字段映射和 mock 写入策略。
- 字段映射支持自动匹配、手动调整、类型冲突和缺失字段提示。

### 4.4 校验、预览与试运行

- 支持当前节点校验和全流程校验。
- 检查断开的节点、缺失配置、重复输出、字段不存在和类型不兼容。
- 支持查看节点输入/输出 Schema、样例数据和数据统计。
- 支持运行当前节点、运行至当前节点、运行下游和运行全流程。
- 节点显示等待、运行中、成功、失败和已停止状态；底部展示日志、输入/输出行数、过滤行数、耗时和错误。
- 失败后支持从失败节点重新运行。

### 4.5 ETL 验收标准

- **ETL-AC-01** 可以完成“输入 → 过滤 → 聚合 → 输出”的画布搭建、保存和恢复。
- **ETL-AC-02** 断线、环路、缺少必填配置或字段类型冲突时禁止发布。
- **ETL-AC-03** 试运行能展示逐节点状态、指标、日志和失败定位。
- **ETL-AC-04** 刷新页面后节点位置、连线和节点配置仍然存在。
- **ETL-AC-05** 发布后生成可供调度引擎引用的不可变版本。

## 5. SQL 开发 · SQL Development

### 5.1 脚本管理

- 支持检索、创建、复制、重命名、删除和归档 SQL 脚本。
- 列表展示数据源上下文、版本、发布状态、最近执行结果、负责人和更新时间。
- 一个脚本可以包含多条 SQL；发布时必须明确任务入口和输出对象。

### 5.2 SQL 编辑器

- 编辑器采用左侧数据目录、中间多标签代码编辑区、底部结果面板和右侧参数/版本面板。
- 支持语法高亮、行号、括号匹配、代码折叠、查找替换、格式化、快捷注释和撤销重做。
- 支持数据对象、字段和 SQL 关键字的 mock 自动补全。
- 明确展示当前数据源、数据库和 Schema 上下文。

### 5.3 参数与安全

- 支持字符串、数字、日期和布尔参数，包含名称、类型、默认值、必填和说明。
- 试运行可以临时覆盖参数值，但不得修改已保存默认值。
- 高风险 DDL/DML 语句显示风险标识；当前原型只模拟结果，不执行真实语句。

### 5.4 校验、执行与结果

- 支持语法校验、当前语句执行、选中 SQL 执行和完整脚本执行。
- 错误包含行号、列号、原因和修改建议，并能定位到编辑器位置。
- 可配置最大返回行数和 mock 超时时间。
- 结果面板包含数据结果、执行日志、错误信息和执行计划。
- 表格结果支持分页、排序、列宽调整和复制单元格，并展示返回行数、扫描数据量、耗时和执行时间。

### 5.5 版本与发布

- 版本保存 SQL 内容、参数、数据源上下文、输出声明、变更说明和创建人。
- 支持查看历史版本、比较差异和将历史内容恢复为新草稿。
- SQL 血缘由 mock 解析结果生成输入/输出引用，不提供可编辑流程画布。

### 5.6 SQL 验收标准

- **SQL-AC-01** 可以编辑、格式化并持久化完整 SQL 文本。
- **SQL-AC-02** 可以分别执行当前语句、选中内容和完整脚本。
- **SQL-AC-03** 结果面板覆盖表格结果、空结果、超时和语法错误。
- **SQL-AC-04** 语法或运行错误能够定位到具体行列。
- **SQL-AC-05** 版本比较能够展示 SQL、参数和上下文差异。
- **SQL-AC-06** 只有校验通过且已声明输出的版本可以发布。

## 6. Notebook 开发 · Notebook Development

### 6.1 Notebook 管理

- 支持检索、创建、复制、重命名、删除和归档 Notebook。
- 支持从空白、SQL 分析或 Python 探索模板创建。
- 列表展示运行时、单元数、最近执行状态、输出摘要、检查点、负责人和更新时间。

### 6.2 单元格编辑

- 支持 Markdown、SQL、Python、R 和参数单元格。
- 支持新增、删除、复制、上下移动和类型切换。
- 代码单元保存源码、执行序号、执行状态、耗时和输出。
- Markdown 标题自动形成文档大纲。

### 6.3 运行时与执行

- 支持 Python、SQL + Python 和 R 等 mock 运行时。
- 展示内核未启动、启动中、空闲、忙碌、失败和已停止状态。
- 支持运行当前单元、运行上方、运行下方、运行全部、停止执行和重启内核。
- 修改已执行单元后，将自身及受影响的后续结果标记为可能过期。
- 当前单元失败时默认停止后续执行，并允许用户选择继续。

### 6.4 输出、变量与检查点

- 输出类型包括文本、表格、日志、图片占位、指标卡和错误堆栈。
- 输出支持折叠、清除和保存为快照。
- 变量面板展示名称、类型、摘要、产生单元和更新时间。
- 重启内核后清空变量，但保留代码和已保存输出快照。
- 手动检查点保存代码、参数、运行时和输出快照。

### 6.5 发布与可复现性

- 发布前必须执行“从干净内核运行全部”校验。
- 发布版本固定单元顺序、参数、运行时和代码内容。
- 存在过期结果、隐藏状态依赖或完整运行失败时禁止发布。

### 6.6 Notebook 验收标准

- **NB-AC-01** 可以增删、移动和切换不同类型的单元格。
- **NB-AC-02** 刷新后代码、顺序、执行状态和输出快照能够恢复。
- **NB-AC-03** 执行单元后正确更新执行序号、内核状态和输出。
- **NB-AC-04** 重启内核会清空变量，并保留代码和已保存输出。
- **NB-AC-05** 存在过期结果或完整运行失败时禁止发布。
- **NB-AC-06** 发布版本能够被调度引擎作为 Notebook 任务引用。

## 7. 非目标 · Non-goals

- 不在当前仓库实现真实 ETL、SQL、Python 或 R 执行。
- 不安装真实 Notebook 包、启动 GPU 资源或管理计算集群。
- 不在数据开发中重复建设调度 DAG、生产运维监控或数据资产审批页面。
- 不新增测试中心、测试菜单或面向用户的测试页面。
