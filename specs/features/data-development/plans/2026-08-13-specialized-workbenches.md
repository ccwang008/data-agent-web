# Data Development Specialized Workbenches Plan

## 目标

将数据开发从三套同构的“列表 + 表单 + mock 运行”页面深化为三种专业开发工作台：可视化 ETL、SQL 编辑器和 Notebook，同时保持 SQLite 持久化 mock 与现有菜单入口稳定。

## 当前基线

- `/data-development/etl`、`/sql`、`/notebook` 已存在。
- 三页当前共用 `EntityWorkspace`，只覆盖列表、基础 CRUD 和单一 mock 运行反馈。
- 三个 `data-agent.data-development.*` SQLite scope 已建立。
- 真实连接器、执行引擎和 Notebook 内核不在当前仓库范围内。

## 实施阶段

### 阶段一：领域模型和页面骨架

1. 建立共享开发对象引用、版本、运行和发布契约。
2. 拆分 ETL、SQL、Notebook 目录、类型、fixture、状态与路由。
3. 保留现有三个菜单入口，增加列表到专业编辑器的站内导航。

### 阶段二：三类专业编辑器

1. ETL：节点库、DAG 画布、属性面板、字段映射、校验和节点级运行反馈。
2. SQL：数据目录、多标签编辑器、参数、校验、结果、错误定位和版本比较。
3. Notebook：单元格、运行时、执行顺序、输出、变量、检查点和结果过期提示。

### 阶段三：统一发布与跨域衔接

1. 为三类对象生成不可变发布版本。
2. 通过 `ArtifactRef` 与调度任务衔接。
3. 保存输入/输出引用、mock 血缘和审计事件。
4. 完成 i18n、状态覆盖、类型检查、构建和 SQLite 检查。

## 约束

- feature 之间禁止直接 import；跨域契约通过共享层或 mock API 传递。
- 不接入真实 ETL、SQL、Python 或 R 执行能力。
- 不保存敏感凭证，不新增面向用户的测试模块。
- 详情路由只有在页面和 mock 数据完成后，才能登记为当前已上线入口。

## 完成定义

- 三类工作台具有可感知、可验证的不同交互范式。
- 草稿、版本、运行和输出在刷新后可恢复。
- 失败可定位到节点、SQL 行列或 Notebook 单元格。
- 已发布版本可被调度通过稳定引用使用，且不会随草稿编辑变化。

## 实施结果

2026-08-13 已完成专业工作台 P0：三类列表与详情路由、ETL DAG 画布、SQL 脚本工作台、Notebook 单元格工作台、SQLite 状态、mock 运行和不可变版本引用。跨域血缘/审计跳转与完整 i18n 保留为后续任务。
