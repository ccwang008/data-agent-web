# Data Agent 一级模块与任务工作区实施计划

## 背景

平台已有数据资产、标准、治理、开发、调度、运维和安全工作台，但 AI 能力主要以局部建议出现。经产品访谈确认，新增一级 Data Agent 模块，通过通用 Agent 自动路由到五个领域 Agent，并以共享任务串联计划、动作、产物、证据和确认。

## 已确认决策

1. Data Agent 是一级产品模块，覆盖“AI 不设独立一级入口”的旧规则。
2. 二级入口为通用 Agent、数据发现 Agent、数据问答 Agent、数据开发 Agent、数据治理 Agent和数据运维 Agent。
3. 不建设任务中心；每个 Agent 进入后先看到自己的任务 List。
4. 跨 Agent 任务只有一份记录，通过参与 Agent 出现在多个列表中。
5. 每个 Agent 使用“首页任务 List + 独立任务详情”，六种详情工作区必须体现专业差异。
6. 读取与分析自动执行，业务变更确认后执行，受控事项回到原审批流程。
7. 每个 Agent 至少提供三个可交互案例，案例可重放并持久化到 SQLite。

## 实施顺序

### M1 · 领域与导航

- 新增 `data-agent` feature、路由和菜单稳定 key。
- 建立共享任务类型、案例 fixture、React provider 和 SQLite scope。
- 注册中英文 namespace，更新产品范围和 ADR 索引。

### M2 · Agent 首页

- 实现任务 List、自然语言输入、上下文接入提示和案例卡。
- 使用参与 Agent 过滤共享任务；通用 Agent 默认作为 `/data-agent` 入口。
- 支持启动、继续、重新演示和全部恢复。

### M3 · 六种任务详情

- 通用：意图识别、Agent 路由、步骤编排、跨域汇总。
- 发现：候选资产、对比矩阵、质量安全和证据。
- 问答：结论、图表、指标口径、数据来源和置信度。
- 开发：需求、SQL/DAG 预览、版本差异、校验和试运行。
- 治理：治理范围、问题研判、影响对象、整改方案和责任链。
- 运维：链路拓扑、运行时间线、根因排序、恢复 Runbook。

### M4 · 跨域入口与验证

- 提供共享 `DataAgentContextLink`，在少量高价值页面携带对象类型与稳定 ID 发起任务。
- 运行构建、测试与菜单路由一致性检查。
- 启动本地原型，逐一验证六个首页、六个详情、案例重放和上下文深链。

## 完成定义

- Data Agent 一级菜单和六个二级菜单均可访问。
- 每个 Agent 至少有三个可交互案例和自己的任务 List。
- 共享案例能从不同 Agent 视角打开同一任务并保持状态一致。
- 六个详情页的信息架构可明显区分，且不存在六个换标题的聊天壳。
- 所有状态遵守 SQLite mock、人工确认和原产品域事实所有权边界。
