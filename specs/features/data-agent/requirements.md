# Data Agent · Requirements

> 关注 **WHAT**：为跨数据资产、问答、开发、治理和运维的 AI 任务提供统一入口、专业工作区与可复核的 Demo 过程。

## 概述 · Overview

平台需要把分散在各产品域的 AI 辅助能力组织为可交互的一级 Data Agent 模块。用户可以直接选择专业 Agent，也可以由通用 Agent 理解需求、自动路由一个或多个领域 Agent，并在同一任务身份下查看计划、产物、证据和确认动作。

## 目标用户 · Personas

| 角色 · Role | 场景 · Scenario | 期望产出 · Outcome |
|---|---|---|
| 业务用户 / 数据分析师 | 不确定数据在哪里，或需要自然语言获取业务结论 | 可信数据候选、指标结论、图表、口径与来源 |
| 数据工程师 | 从自然语言需求生成或优化 SQL、ETL、Notebook | 可确认的开发草稿、差异、校验和试运行解释 |
| 数据治理人员 | 检查标准、元数据、质量、安全与责任问题 | 治理差距、影响分析、整改候选和审批状态 |
| 运维管理员 | 诊断任务失败、链路异常和资源风险 | 根因排序、运行时间线、恢复方案与执行反馈 |
| 平台演示人员 | 连续演示一项数据需求在多个 Agent 间协作 | 可重放的贯穿式案例与稳定 mock 状态 |

## 用户故事 · User Stories

- **US-01** 作为不确定专业入口的用户，我希望向通用 Agent 描述需求，以便系统自动选择和协调相关领域 Agent。
- **US-02** 作为业务用户，我希望比较候选资产的语义、质量、安全和血缘，以便选择可信数据。
- **US-03** 作为业务用户，我希望基于批准口径获得带图表和证据的数据回答，以便复核结论。
- **US-04** 作为数据工程师，我希望把需求生成 SQL/ETL/Notebook 草稿并查看差异和校验，以便进入专业编辑器继续工作。
- **US-05** 作为数据治理人员，我希望跨标准、元数据、质量和安全识别问题并生成整改候选，以便进入原职责链处理。
- **US-06** 作为运维管理员，我希望从异常运行追踪链路、根因和恢复动作，以便安全地确认重试或转交开发修复。
- **US-07** 作为平台用户，我希望在资产、开发、治理和运行页面把当前对象交给 Data Agent，以便保留上下文发起任务。
- **US-08** 作为演示人员，我希望重放单个案例或恢复全部示例，以便重复演示不同状态。

## 验收标准 · Acceptance Criteria (EARS)

- **AC-01** 当用户进入 `/data-agent` 时，系统应当默认打开通用 Agent 首页并展示其任务 List、自然语言入口和至少三个案例。
- **AC-02** 当用户进入任一领域 Agent 时，系统应当展示该 Agent 参与的共享任务，不复制跨 Agent 任务记录。
- **AC-03** 当用户打开一个任务时，系统应当按当前 Agent 视角呈现专属工作区，并保留同一任务 ID、参与 Agent、计划、证据和产物。
- **AC-04** 当通用 Agent 处理跨域案例时，系统应当展示意图识别、Agent 路由、执行顺序、中间产物和汇总结果。
- **AC-05** 当用户触发读取、检索、分析或诊断动作时，系统应当允许 mock 自动推进并记录结果。
- **AC-06** 当动作会改变平台业务状态时，系统应当先展示变更预览和确认入口；受控动作不得在 Data Agent 内完成最终批准。
- **AC-07** 当用户需要复杂编辑时，系统应当提供指向原专业工作台的稳定跳转，并携带对象引用。
- **AC-08** 当用户选择案例时，系统应当提供可操作的步骤、候选、图表、代码、整改或恢复动作，而不是只展示静态介绍。
- **AC-09** 当用户重放单个案例时，系统应当只恢复该案例对应的 Agent mock 任务；恢复全部案例不得删除其他产品域的业务状态。
- **AC-10** 当用户刷新页面时，当前任务状态和案例进度应当从本地 SQLite 恢复。
- **AC-11** 当任务展示 AI 过程时，系统应当展示计划、动作、对象引用、证据、置信度和未决信息，不展示模拟思维链。
- **AC-12** 当用户从关键业务页面发起 Data Agent 时，系统应当通过对象类型和稳定 ID 传递上下文，不复制业务正文。

## 范围 · In Scope

- 一级 Data Agent 菜单、六个二级 Agent 菜单及首页/任务详情路由。
- 共享 Agent 任务、任务步骤、证据、产物、确认动作和参与 Agent 数据模型。
- 六个 Agent 的任务 List 首页与六种专属任务详情工作区。
- 每个 Agent 至少三个可交互案例：一个共享零售主案例和两个专项案例。
- 单案例重放、全部案例恢复、SQLite 状态和审计事件。
- 资产、开发、质量问题、调度或运维页面的少量上下文入口。
- 中文与英文基础命名及关键 UI 文案。

## 非目标 · Out of Scope

- 不接入真实 LLM、向量检索、生产数据库、Notebook 内核或调度执行器。
- 不建设独立任务中心、工作流设计中心、提示词管理中心或模型管理中心。
- 不在 Data Agent 内复制完整 SQL/ETL 编辑器、调度画布、标准维护或安全审批页面。
- 不让 Agent 自动批准标准发布、重要/核心数据等级、安全授权或问题关闭。
- 不保存真实敏感数据、连接凭证、推理日志或模型权重。
- 不实现严格的长期会话、任务验收和目标变更状态机；首期只保留 Demo 所需的简化状态。

## 依赖 · Dependencies

- 上游 · Upstream: 数据资产目录、数据标准、元数据与质量、数据开发版本、调度运行、运维监控和数据安全的稳定对象引用。
- 下游 · Downstream: 专业工作台深链、量化看板 AI 证据引用。
- 外部 · External: 无；首期使用本地 SQLite 与 mock 案例。

## 风险与未决 · Risks & Open Questions

- 多 Agent 任务在真实后端接入后需要统一的授权、幂等、并发与补偿协议，当前不在原型范围。
- 上下文入口首期只覆盖高价值页面，后续扩展必须避免给所有页面机械添加 AI 按钮。
