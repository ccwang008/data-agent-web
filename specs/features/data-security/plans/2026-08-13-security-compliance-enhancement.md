# Data Security · 数据安全合规增强计划（2026-08-13）

> 本文归档本次 `grill-with-docs` 访谈形成的完整计划。当前轮次只交付功能设计文档，不实施目标页面代码。

## 建设目标

将数据安全从“有防护”升级为“能举证”，建设面向 DCMM 第4级就绪度的数据安全合规与证据工作台。产品完整覆盖 GB/T 36073—2025 第 12 章的数据合规管理、数据安全防护和数据安全审计，并在用户提出的四项核心需求上重点深化：

1. AI 数据分类分级引擎。
2. 安全审计报告自动生成。
3. 数据出境合规评估。
4. 安全事件响应 SOP 和记录系统。

访谈追加的脱敏、加密和数据水印作为独立三级功能建设。

## 产品承诺边界

- 定位为“面向 DCMM 第4级（量化管理级）的数据安全合规与证据管理工作台”。
- 系统负责识别风险、汇集证据、量化评价、生成报告和跟踪整改。
- 系统不自动认定组织达到 DCMM 第4级，不替代外部评估、监管批准或法律意见。
- 中国大陆作为首版合规法域，法规和检查规则必须版本化。
- 当前 SQLite 原型只模拟状态、执行和证据，不执行生产安全控制。

## 确认的信息架构

一级菜单为“数据安全”，下设六个二级能力域：

| 二级能力 | 三级菜单 |
|---|---|
| 安全总览 | 安全驾驶舱 |
| 数据合规管理 | 合规清单、合规审查、个人信息管理、重要数据管理、数据出境评估 |
| 数据分类分级 | 识别任务、复核审批、分类分级规则、分类分级报告 |
| 安全防护 | 防护策略、访问控制、脱敏管理、加密管理、数据水印、安全监控与风险 |
| 安全审计 | 审计计划、审计执行、审计证据、审计报告、问题整改 |
| 安全事件响应 | 事件台账、响应 SOP、通知与报告、演练与复盘 |

## 已确认的关键决策

### 1. 职责分离

- 分类分级：AI 提议，数据负责人确认，数据安全负责人批准重要/核心等级。
- 出境评估：业务提交，法务合规和数据安全双重审批。
- 安全审计：审计人员独立形成结论，数据安全负责人负责整改但不改写结论。
- 安全事件：响应人员处置，独立复核后关闭。

### 2. 分类分级双轴模型

- 数据项是最小判定对象。
- 分类可多选，包括个人信息、敏感个人信息、经营、财务、研发和商业秘密等。
- 安全等级单选，包括一般数据、重要数据和核心数据；一般数据可细分常规一般与敏感一般。
- 个人信息不自动等于重要数据。

### 3. AI 权限边界

- 高置信度且无冲突的普通分类可以自动生效并进入抽样复核。
- 低置信度或冲突结果进入人工复核。
- AI 对重要数据、核心数据只能形成候选及依据，不能自动生效。
- 所有结果保留模型、规则、置信度、证据和审批版本。

### 4. 资产等级与影响传播

- 资产默认继承最高数据项等级。
- 规模、精度、覆盖度、关联性和使用场景可触发组合升级。
- 系统不得自动降级。
- 等级提高或新增敏感项后，相关产品、授权、出境场景和保护策略进入待复核。

### 5. 最少暴露

- 优先使用元数据，内容识别只用受控抽样或脱敏片段。
- 不保存原始敏感值、完整文档、密码、token、真实密钥、私钥或完整连接串。
- 证据只保存脱敏示例、统计特征、稳定引用和校验状态。

### 6. 报告版本

- 分类、出境、审计和事件复盘报告固定范围、依据、结果、证据和审批。
- 已批准报告不可覆盖；修订生成新版本。
- mock 导出明确标记非认证、非监管材料。

### 7. 审计证据所有权

- 原始访问、流转、交换、操作和执行事件由来源域拥有。
- 数据安全只建立稳定证据引用、完整性校验和证据缺口。
- 访问、流转和交换行为是审计证据，不等同于完整安全审计。

### 8. 四类审计和一键报告

- 审计类型为过程、规范、合规和供应商审计。
- 一键生成完成证据汇聚、校验、指标、异常聚类、根因候选和草稿。
- 审计人员复核后发布，证据不足必须限制结论。
- 内外部审计结果可以关联，外部报告不能由原型伪造。

### 9. 出境场景与路径建议

- 出境场景而非单次请求是管理对象。
- 场景固定处理者、目的、数据范围、接收方、渠道、期间、累计数量和保护措施。
- 引擎输出豁免、标准合同/认证、安全评估、信息不足或专家审查等路径建议。
- 内部评估完成不等于监管批准。
- 场景或规则实质变化触发重新评估，历史报告保持原版本。

### 10. 量化管理

- 指标有稳定 ID、定义、公式、分子分母、来源、范围、周期、目标、趋势、责任人、规则版本和证据。
- 无来源或分母不完整时显示未知，不显示零风险或 100%。
- DCMM 控制项指标表达就绪度，不表达认证通过率。

### 11. 脱敏、加密和水印

- 脱敏支持静态/动态及掩码、泛化、替换、哈希、令牌化策略。
- 加密管理传输、存储、字段级策略、算法、密钥引用和轮换状态，不保存真实密钥。
- 水印支持显式提示与隐式追踪，记录模拟嵌入、验证和来源追踪。
- 三类策略关联分类版本、场景、负责人、审批、版本和执行证据。

### 12. 轻量事件响应

- 区分安全信号、疑似事件和安全事件。
- 严重性为 S1–S4，综合数据等级、影响人数、业务中断、跨境等因素。
- SOP 只采用研判、处置、恢复、通知、复盘五阶段检查清单。
- 通知义务由版本化法源生成建议，法务合规确认最终路径。
- 原型不发送真实通知。

## 实施阶段

### 阶段 0：模型与迁移

1. 建立共享证据契约和六个分域 SQLite scope。
2. 将旧混合分类/L1–L4 数据标记待映射。
3. 将旧脱敏记录复制为保护策略草稿，加密说明拆为独立策略。
4. 建立确定性 mock 任务、规则和版本工具。

### 阶段 1：合规和证据 P0

1. 安全驾驶舱与可追溯量化指标。
2. 合规清单、合规审查、个人信息和重要数据管理。
3. 双轴分类、复核审批和分类报告。
4. 数据出境评估和版本化路径建议。
5. 四类审计、来源证据、一键草稿和整改。
6. 对应一级/二级/三级菜单和路由。

### 阶段 2：防护和事件 P1

1. 防护策略和访问控制。
2. 独立脱敏、加密和数据水印页面。
3. 安全监控、风险评估和知识库。
4. 安全事件台账、轻量 SOP、通知、演练和复盘。

### 阶段 3：联动和体验 P2

1. 与数据资产的分类版本、产品和授权复核联动。
2. 与数据集成、开发、调度、运维和设置的证据引用联动。
3. 统一报告、证据包、i18n、分页、可访问性和全状态反馈。
4. 全部页面完成后切换 `/data-security` 默认入口到 `/overview`。

## 验证门槛

- 三级菜单的每个目标必须有实际路由和页面后才能标记 ready。
- 分类自动生效、重要/核心审批、组合升级、禁止自动降级和旧数据迁移有纯函数测试。
- 出境路径、规则变更影响、证据完整性和指标未知值有确定性测试。
- 审计报告无法绕过人工复核，批准版本不可覆盖。
- S1/S2 事件无法跳过复盘和独立关闭复核。
- SQLite 刷新恢复、scope 迁移、敏感字段拒绝和 mock 标识通过验证。
- 运行 `typecheck`、`lint`、测试、构建和 `db:inspect`。
