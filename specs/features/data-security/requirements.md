# Data Security · 数据安全需求

> 状态：2026-08-13 需求访谈已确认。本文描述目标产品能力；当前代码仅实现 `/classification` 和 `/masking` 两个基础 SQLite mock 页面，差距见 [tasks.md](./tasks.md)。

## 建设目标 · Goal

将数据安全能力从“有防护”升级为“能举证”，建立面向数据安全负责人、法务合规、独立审计和事件响应人员的合规与证据工作台。产品覆盖 GB/T 36073—2025 第 12 章的数据合规管理、数据安全防护和数据安全审计，并按第4级“量化管理级”要求提供量化指标、人工智能辅助、内外部评估协同、证据追溯和持续改进。

产品只表达 DCMM 第4级就绪度和内部管理结果，不自动认定组织达到 DCMM 第4级，不替代外部评估、监管批准或法律意见。

## 简化原则 · Simplification

- 使用固定业务状态和固定审批模板，不建设通用工作流设计器。
- 安全事件 SOP 采用“研判、处置、恢复、通知、复盘”五阶段轻量检查清单，不建设复杂步骤编排引擎。
- 规则、报告和证据都版本化；历史结论不可覆盖。
- 当前 SQLite 原型只模拟扫描、策略执行、审计、出境评估、事件和通知结果，不执行真实安全控制。

## 目标用户与职责 · Personas

| 角色 | 核心场景 | 职责分离 |
|---|---|---|
| 数据安全负责人 | 管理规则、风险、证据完整性、量化指标和报告发布 | 不代替法务作法律结论，不修改独立审计结论 |
| 数据负责人 | 确认数据项业务含义和分类分级候选 | 不批准自己提交的重要/核心数据结论 |
| 法务合规人员 | 确认合规路径、出境义务和事件通知路径 | 与业务申请人分离 |
| 审计人员 | 执行过程、规范、合规和供应商审计 | 不修改来源域原始事件，不负责整改后自行关闭 |
| 事件响应人员 | 研判、处置、恢复、通知和复盘 | 不独立复核自己处置的事件 |
| 业务申请人 / 资产运营人员 | 提交合规审查、出境场景和策略例外 | 不审批自己的申请 |

| 12.2 数据安全防护 | 分类分级、防护策略、访问控制、监控、脱敏、加密、水印、风险评估和事件响应 |

## 量化管理 · Quantitative Management

每项指标必须具有指标 ID、定义、公式、分子、分母、数据来源、适用范围、周期、目标值、预警阈值、实际值、趋势、责任人、规则版本和证据引用。目标值由组织配置，不宣称是国标固定门槛。

| 指标 | 计算口径 |
|---|---|
| 分类分级覆盖率 | 已有生效分类分级记录的数据项 / 应分类数据项 |
| 分类复核及时率 | 在要求时限内完成复核的候选 / 到期应复核候选 |
| 分类识别误报率 | 抽样复核判为错误的自动结果 / 已抽样自动结果 |
| 分类等级过期率 | 已超过复核周期的生效记录 / 全部生效记录 |
| 保护策略覆盖率 | 已关联有效保护策略的受管数据项 / 应保护数据项 |
| 异常行为发现率 | 由监控规则识别的有效异常 / 已确认异常总数 |
| 风险整改按期率 | 按期完成并复核的风险整改 / 到期风险整改 |
| 平均响应时间 | 安全事件确认时间与首次发现时间的平均差值 |
| 平均恢复时间 | 安全事件恢复验证时间与确认时间的平均差值 |
| 审计证据完整率 | 已采集且校验通过的必需证据 / 应采集必需证据 |
| 安全审计覆盖率 | 已完成审计的范围对象 / 审计计划范围对象 |
| 审计整改关闭率 | 已独立复核关闭的问题 / 到期应关闭问题 |
| 重大问题复发率 | 统计期内重复发生的重大问题 / 已关闭重大问题 |
| 出境评估覆盖率 | 已完成内部评估的有效出境场景 / 全部有效出境场景 |
| 合规规则过期率 | 已失效但仍被有效场景引用的规则 / 被有效场景引用的规则 |
| 待重新评估场景数 | 因场景或规则实质变化进入待重新评估的场景数量 |
| DCMM 控制项证据覆盖率 | 已具备有效证据的适用控制项 / 全部适用控制项 |

当来源缺失、分母不完整或证据不可校验时，指标显示“未知/证据不足”，不得用 0 或 100% 代替。

## 功能需求 · Functional Requirements

### FR-01 安全总览

- 以安全驾驶舱展示数据合规管理、安全防护和安全审计三域的 DCMM 第4级就绪度。
- 展示量化指标、趋势、证据缺口、逾期整改、高风险出境场景和重大事件待办。
- 管理制度、培训、演练、外部评估和标准参与等组织证据，不将证据上传等同能力达成。
- 控制项状态为“不适用、证据不足、待整改、基本就绪”，不提供“已认证”状态。

### FR-02 数据合规管理

- 合规规则包记录法域、权威来源、版本、生效/失效日期和替代关系。
- 首版使用中国大陆合规基线，重点覆盖个人信息、重要数据、核心数据和数据出境。
- 合规清单把规则要求映射到责任人、适用对象、证据、检查状态和整改。
- 合规审查支持新项目、数据处理活动和专项审查，输出风险、改进建议和复核记录。
- 个人信息管理记录处理目的、必要性、处理方式、同意或其他依据、影响评估和接收方证据引用。
- 重要数据管理维护候选、生效记录、行业目录或监管依据、申报/保护证据及变更历史。
- 外部合规评估只登记机构、范围、期间、报告引用和改进事项，不模拟外部评估结论。

### FR-03 数据分类分级引擎

- 以数据项作为最小判定对象：结构化字段、JSON/XML 路径、API 请求/响应字段或非结构化内容中的敏感区域。
- 识别时优先使用字段名、类型、注释、业务术语和血缘；内容识别仅使用受控抽样或脱敏片段。
- 系统只保存命中类型、脱敏示例、统计特征、置信度、规则/模型版本和证据引用，不保存原始敏感值或完整文档。
- “分类”和“安全等级”使用双轴模型：分类可多选，安全等级单选。
- 分类包括个人信息、敏感个人信息、经营、财务、研发、商业秘密等组织分类；个人信息不自动等于重要数据。
- 安全等级包括一般数据、重要数据和核心数据；一般数据可按适用规则细分为常规一般数据和敏感一般数据。
- 高置信度且无冲突的普通分类可以自动生效并进入抽样复核；低置信度或冲突结果进入人工复核。
- AI 对重要数据和核心数据只能提出候选及依据，必须由数据负责人确认、数据安全负责人批准后生效。
- 资产级等级默认继承最高数据项等级；规模、精度、覆盖度、关联性或使用场景可以触发组合升级。
- 系统不得自动降级；降级需重新扫描、说明变化并通过复核批准。
- 分类等级提高或新增敏感项时，关联的数据产品、授权、出境场景、脱敏、加密和水印策略进入待复核。
- 分类分级报告固定扫描范围、资产/数据项版本、覆盖率、排除项、规则/模型版本、结果、冲突、调整、影响和审批。
- 报告状态为“草稿、待复核、已批准、已失效”；已批准版本不可覆盖。

### FR-04 防护策略与访问控制

- 防护策略把生效分类分级记录映射到生命周期保护要求、责任人、审批和执行证据。
- 支持人员、部门、内部系统和外部机构对资产、字段、API 或文件的用途、范围、期限和配额策略。
- 支持越权访问、高频下载、异常交换等监控规则、安全信号和风险清单。
- 策略例外必须记录申请人、范围、原因、补偿措施、有效期和审批。
- 当前原型只模拟策略校验和执行结果，不实现真实 IAM、DLP 或监控采集。

### FR-05 脱敏管理

- 支持静态脱敏和动态展示脱敏策略。
- 支持掩码、泛化、替换、哈希和令牌化等规则类型。
- 规则关联数据项类型、适用资产、使用场景、使用方、分类版本、负责人和审批。
- 预览仅使用虚构或脱敏样例，不展示真实敏感数据。
- 保留策略版本、模拟执行记录、例外、失败和整改证据。

### FR-06 加密管理

- 支持传输、存储和字段级加密策略。
- 记录算法、适用范围、密钥引用、轮换状态、到期提醒、负责人和审批。
- 系统不得保存真实密钥、私钥或可还原凭证。
- 加密覆盖率只能基于模拟执行证据计算，不得因配置存在即显示已实施。

### FR-07 数据水印

- 支持报告、预览和导出文件的显式水印策略。
- 支持下载文件或结构化数据副本的隐式追踪水印策略。
- 水印模板可包含使用方、授权、用途、时间和追踪 ID。
- 记录模拟嵌入任务、水印标识、验证结果和泄露来源追踪记录。
- 当前原型不执行真实嵌入、提取或抗攻击算法。

### FR-08 数据出境合规评估

- 以出境场景作为管理对象，不以单次传输请求作为评估对象。
- 场景记录境内处理者、是否属于关键信息基础设施运营者、目的、必要性、数据资产/数据项、分类版本、自然人数、境外接收方、国家/地区、受托方、再转移、渠道、频率、期间和保护措施。
- 按自当年 1 月 1 日起的自然人去重口径记录累计个人信息和敏感个人信息数量。
- 记录合同、单独同意、个人信息保护影响评估及其他材料的证据引用。
- 引擎输出“信息不足、可适用豁免、建议标准合同或认证、应申报安全评估、高风险待专家审查、内部评估完成”等管理状态。
- 每项建议展示规则版本、输入事实、命中路径、未满足项和人工调整理由。
- 法务合规和数据安全双重审批后，场景才可进入“内部允许执行”；该状态不代表监管批准。
- 目的、接收方、数据范围、安全等级或规则版本发生实质变化时触发重新评估。
- 新规则不回写历史报告；影响分析只标记有效或进行中场景并生成新评估版本。

### FR-09 数据安全审计与自动报告

- 数据安全审计覆盖过程审计、规范审计、合规审计和供应商审计。
- 数据访问、流转、交换、操作和执行的原始事件由来源域拥有；数据安全模块只按稳定事件 ID 建立证据目录。
- 证据目录记录来源、期间、完整性校验、采集状态和证据缺口，不复制或修改来源事件。
- 审计计划记录类型、范围、期间、团队、抽样策略和内外部审计关联。
- 审计执行记录检查项、工作记录、证据、发现、业务/经济影响、根因和改进建议。
- “一键生成”自动完成证据汇聚、完整性检查、指标计算、异常聚类、根因候选和报告草稿。
- 证据不足时报告必须标明限制，不能将缺失解释为“符合”或“无异常”。
- 审计人员独立复核并形成结论；数据安全负责人负责整改分派，不得改写审计结论。
- 报告批准后冻结；修订生成新版本或补充报告。
- 审计问题记录严重性、责任人、期限、方案、证据和独立复核，复核通过后方可关闭。

### FR-10 安全事件响应

- 区分安全信号、疑似安全事件和安全事件；被排除案件仍保留研判依据。
- 安全事件使用 S1 特别重大、S2 重大、S3 较大、S4 一般四级严重性。
- 判级综合数据等级、个人信息敏感性、影响人数和范围、业务中断、跨境因素、持续时间和可恢复性。
- 事件记录使用“研判、处置、恢复、通知、复盘”五阶段轻量 SOP。
- 每阶段仅记录负责人、状态、结果、时间和附件；不建设复杂步骤依赖或流程编排。
- S1/S2 必须完成复盘和独立关闭复核；紧急处置可以先执行，但必须补录原因和授权。
- 通知义务由事件事实、数据类别/等级、行业、法域和规则版本生成，状态为“需要通知、无需通知、待法务判断”。
- 记录首次发现、确认、处置、恢复、通知决定、实际通知和逾期原因。
- 支持演练计划、结果、问题、改进和知识库沉淀。
- 原型不向监管机构、个人、客户或合作方真实发送通知。

### FR-11 通用证据与报告

- 重要对象均具有稳定 ID、版本、责任人、状态、来源、创建/更新时间、审批和变更历史。
- 证据记录包含证据 ID、类型、来源域、来源记录 ID、期间、脱敏引用、完整性校验和保全状态。
- 已批准分类报告、出境评估报告、安全审计报告和事件复盘不得业务覆盖或普通删除。
- 导出包至少包含报告、指标口径、规则版本、证据清单、审批记录和限制说明。
- mock 报告必须显示“原型演示/非认证结论/非监管材料”标识。

## 关键场景 · Scenarios

### 场景 A：AI 识别敏感个人信息

系统从客户表元数据和脱敏抽样中识别手机号字段，生成“个人信息 + 敏感个人信息”高置信度分类。结果自动生效并进入抽样复核；报告记录规则、模型、置信度和脱敏证据，不保存真实手机号。

### 场景 B：重要数据只能成为候选

AI 根据业务语义和规模提出重要数据候选，但没有行业目录或监管依据。系统不得直接生效，必须提示依据缺口，经数据负责人确认和数据安全负责人批准后才形成生效记录。

### 场景 C：等级变化传播影响

客户表新增敏感字段并完成审批后，包含该字段的下载产品、授权和出境场景进入安全待复核；不包含该字段的聚合 API 不受影响。历史产品和报告仍引用原分类版本。

### 场景 D：出境路径建议

业务方登记向境外接收方持续提供个人信息的场景。系统根据处理者身份、数据类别和年度累计人数给出路径建议、材料缺口和风险项；法务合规与数据安全双重审批后只形成内部处理决定。

### 场景 E：审计证据不足

审计报告计划覆盖访问、流转和交换行为，但交换模块证据采集失败。系统仍可生成草稿，但证据完整率显示未知或不足，对应结论标记受限，不得显示全部符合。

### 场景 F：水印辅助事件追踪

某下载文件疑似泄露，响应人员输入水印追踪标识，系统关联到模拟下载任务、使用授权和使用方，形成调查证据；原型只模拟验证结果，不执行真实水印提取。

## 验收标准 · Acceptance Criteria

- **AC-01** 当用户查看安全驾驶舱时，系统应当分别展示合规、防护、审计就绪度以及证据缺口，不展示“已认证”。
- **AC-02** 当指标来源或分母不完整时，系统应当显示“未知/证据不足”，不得显示为 0 或 100%。
- **AC-03** 当规则包被新版本替代时，系统应当保留旧版本并列出受影响的有效对象。
- **AC-04** 当创建分类任务时，系统应当允许按资产和数据项范围配置，并记录覆盖率与排除项。
- **AC-05** 当自动结果置信度低或规则冲突时，系统应当进入待复核状态。
- **AC-06** 当 AI 提出重要数据或核心数据时，系统应当只生成候选并要求双人确认。
- **AC-07** 当普通分类满足自动生效条件时，系统应当记录规则、模型、置信度并纳入抽样复核。
- **AC-08** 当资产存在组合风险时，系统应当允许升级资产安全等级并记录依据。
- **AC-09** 当用户申请降低安全等级时，系统应当要求重新评估和复核批准，不得自动降级。
- **AC-10** 当分类报告获批时，系统应当冻结其范围、依据、结果、影响和审批版本。
- **AC-11** 当生效分类发生提高或新增敏感项时，系统应当列出受影响的产品、授权、出境场景和保护策略。
- **AC-12** 当配置脱敏规则时，系统应当区分静态与动态策略，并只用虚构或脱敏样例预览。
- **AC-13** 当配置加密策略时，系统应当保存密钥引用和轮换状态，但拒绝保存真实密钥内容。
- **AC-14** 当配置水印时，系统应当区分显式和隐式策略，并生成可追踪的模拟水印标识。
- **AC-15** 当保护策略模拟执行失败时，系统应当记录失败原因、影响范围和整改状态。
- **AC-16** 当登记出境场景时，系统应当要求处理者、目的、数据范围、接收方、期间和保护措施等关键事实。
- **AC-17** 当出境信息不足时，系统应当停止路径判断并列出缺失事实。
- **AC-18** 当出境路径建议生成时，系统应当展示规则版本、命中条件和材料缺口。
- **AC-19** 当出境场景完成内部审批时，系统应当标记“内部评估完成”，不得标记监管批准。
- **AC-20** 当出境场景或规则发生实质变化时，系统应当生成待重新评估任务并保留历史版本。
- **AC-21** 当建立安全审计时，系统应当允许选择过程、规范、合规和供应商审计类型。
- **AC-22** 当采集来源域事件时，系统应当保存稳定引用和校验状态，不复制可编辑的第二套原始日志。
- **AC-23** 当证据采集失败时，系统应当生成证据缺口并限制相关审计结论。
- **AC-24** 当用户一键生成审计报告时，系统应当先生成待审计人员复核的草稿。
- **AC-25** 当审计报告批准发布时，系统应当冻结版本；后续修改只能形成新版本或补充报告。
- **AC-26** 当审计问题完成整改时，系统应当要求独立复核后才能关闭。
- **AC-27** 当监控产生异常时，系统应当先形成安全信号，不得自动将所有信号认定为事件。
- **AC-28** 当疑似事件被排除时，系统应当保留信号、研判依据和排除结论。
- **AC-29** 当安全事件确认时，系统应当生成 S1–S4 严重性、五阶段 SOP 和责任人。
- **AC-30** 当 S1 或 S2 事件进入关闭时，系统应当校验复盘和独立复核已完成。
- **AC-31** 当通知义务无法确定时，系统应当标记“待法务判断”，不得套用统一固定小时数。
- **AC-32** 当通知任务完成时，系统应当记录决定、审批、实际时间和逾期原因。
- **AC-33** 当用户操作任一安全页面时，系统应当提供正常、空、加载、失败、运行中、成功和已停止等 mock 状态。
- **AC-34** 当页面保存可变状态时，系统应当使用 `data-agent.data-security.*` SQLite scope。
- **AC-35** 当用户尝试录入密码、token、私钥、真实密钥或完整连接串时，系统应当拒绝或只保存脱敏引用。
- **AC-36** 当模拟执行或导出报告时，系统应当显示原型和非认证说明。

## 范围 · In Scope

- 六个二级能力域及其三级菜单的产品设计。
- 中国大陆合规规则基线和可扩展的规则包机制。
- 脱敏 SQLite mock 数据、固定审批模板、证据和报告版本。
- 与数据资产、数据集成、调度、开发、运维和设置模块的稳定 ID/事件引用设计。

## 非目标 · Out of Scope

- 真实数据源、文件或文档扫描和内容读取。
- 真实 IAM、KMS、DLP、加密、脱敏、水印、异常检测或安全态势引擎。
- 真实监管申报、标准合同备案、认证申请、通知发送或外部审计服务。
- 自动法律意见、监管批准判断、DCMM 认证结论或通过保证。
- 通用工作流、复杂事件编排、任意规则脚本或生产级证据防篡改基础设施。
- 保存真实个人信息、敏感数据、密码、token、密钥、私钥或完整连接串。

## 依赖 · Dependencies

- 上游：数据资产的稳定资产/字段 ID 与分类版本引用；数据集成的流转/交换事件；设置、调度、开发和运维的操作/执行事件。
- 下游：数据产品发布门槛、使用授权、下载/API 校验、出境评估和审计报告。
- 外部依据：GB/T 36073—2025、GB/T 43697—2024，以及版本化的中国大陆现行数据安全和出境规则。

## 风险与约束 · Risks

- 法规、行业目录和数据出境阈值会变化，所有结论必须绑定规则版本并支持影响分析。
- AI 结果可能误报或漏报，重要数据和核心数据不得自动生效。
- 来源域事件覆盖不完整会限制审计结论，系统必须显式显示证据缺口。
- 当前基础页面使用混合类别和 L1–L4 mock 等级，实现增强前必须迁移为已确认的双轴模型。
