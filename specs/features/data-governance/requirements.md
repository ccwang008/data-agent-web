# Data Governance · Requirements

## 目标用户 · Personas

| 角色 | 场景 | 期望产出 |
|---|---|---|
| 数据治理人员 | 管理元数据、责任人和血缘 | 可检索、可解释的数据地图 |
| 质量负责人 | 配置规则并关注评分变化 | 可量化、可整改的数据质量 |
| 数据资产运营人员 | 评估数据是否可上架服务 | 有治理依据的可信资产 |

## 用户故事 · User Stories

- **US-01** 作为治理人员，我希望搜索元数据并查看上下游血缘，以便理解数据来源、影响范围和责任人。
- **US-02** 作为质量负责人，我希望配置完整性、准确性等规则并查看评分，以便发现和跟踪质量问题。
- **US-03** 作为治理人员，我希望元数据对象引用明确的数据标准版本和最近稽核结果，以便查看规范性但不复制标准正文。

## 验收标准 · Acceptance Criteria

- **AC-01** 元数据页面应支持对象检索、技术/业务属性、负责人、更新时间和血缘详情。
- **AC-02** 血缘关系应能表达数据源、任务、湖表、指标和数据服务的上下游依赖，并展示影响范围。
- **AC-03** 质量页面应支持规则的创建、编辑、启停、类型、阈值、评分和最近执行结果。
- **AC-04** 质量指标至少覆盖完整性、准确性，并预留及时性、一致性、唯一性等维度。
- **AC-05** 元数据对象应能引用企业标准 ID、版本 ID、本体概念 ID 和最近稽核摘要，并跳转目标 `/data-standard/*` 页面。
- **AC-06** 治理状态可被数据资产目录、调度监控和数据服务发布流程引用。
- **AC-07** `/data-governance/standards` 不作为当前或兼容路由；本 feature 不维护业务术语、主数据、参考数据、数据元或指标字典正文。

## 范围 · Scope

- 元数据、血缘和数据地图
- 数据质量规则、指标、评分和运行结果
- 数据标准稳定引用和稽核摘要

## 非目标 · Out of Scope

- 真实扫描器、探查器、规则执行引擎和血缘采集器
- 业务术语、本体模型、主数据、参考数据、数据元标准、指标字典及其审批；见独立 [`data-standard`](../data-standard/README.md) 规格
- 数据治理组织流程和外部审批系统
- 用前端评分替代生产质量结论
