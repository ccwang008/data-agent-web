# Data Governance · Requirements

本 feature 基于 GB/T 36073—2025 DCMM 第4级（量化管理级）要求重构，覆盖三个产品子模块：治理中心（DCMM 7 数据治理域）、元数据与血缘（DCMM 8.4 元数据管理）、数据质量（DCMM 11 数据质量域）。数据标准正文不在本 feature 维护。

## 目标用户 · Personas

| 角色 | 场景 | 期望产出 |
|---|---|---|
| 数据治理负责人 | 管理治理组织、制度和文化建设 | 跨域治理健康度概览与组织认责体系 |
| 数据治理人员 | 管理元数据、认责和血缘 | 可检索、可解释、可认责的数据地图 |
| 元数据管理员 | 配置元模型和监控元数据质量 | 元模型驱动的规范元数据管理 |
| 质量负责人 | 配置规则、监控评分和跟踪问题 | 可量化、可闭环的数据质量 |
| 质量整改人员 | 接收分发问题并整改复检 | 清晰的问题闭环与职责分离 |
| 数据资产运营人员 | 评估数据是否可上架服务 | 有治理依据和可信度的可信资产 |

## 用户故事 · User Stories

### 治理中心（DCMM 7 数据治理域）

- **US-G01** 作为治理负责人，我希望在一个大盘概览组织、制度、文化健康度和治理问题，以便掌握跨域治理现状。
- **US-G02** 作为治理负责人，我希望管理三级治理组织和岗位职责，以便建立权责清晰的治理责任体系。
- **US-G03** 作为治理负责人，我希望查看认责总览（覆盖率、按业务部门统计、异常清单），以便推动业务部门参与数据治理并量化考核职责落实。
- **US-G04** 作为治理负责人，我希望管理三层制度文档（政策/办法/细则）并跟踪执行情况，以便建立可执行、可监控的制度体系。
- **US-G05** 作为治理负责人，我希望管理数据文化推广活动并量化成效，以便培育数据驱动文化。
- **US-G06** 作为治理人员，我希望个人工作台按角色展示待办，以便驱动日常治理执行。

### 元数据与血缘（DCMM 8.4 元数据管理）

- **US-M01** 作为治理人员，我希望搜索元数据并查看上下游血缘，以便理解数据来源、影响范围和责任人。
- **US-M02** 作为元数据管理员，我希望配置元模型（对象类型、属性集、关系类型、采集规则），以便为元数据采集、质量评价和血缘分析提供规范依据。
- **US-M03** 作为元数据管理员，我希望按元模型指标评价元数据质量（准确/完整/时效），以便发现元数据本身的问题并驱动整改。
- **US-M04** 作为治理人员，我希望在元数据对象详情编辑认责字段（所有者/管理者），以便落实数据认责。
- **US-M05** 作为元数据管理员，我希望查看元数据管理量化指标和定期报告，以便度量元数据管理成效。

### 数据质量（DCMM 11 数据质量域）

- **US-Q01** 作为质量负责人，我希望从综合可信度、维度评分和趋势概览数据质量，以便定位质量短板。
- **US-Q02** 作为质量负责人，我希望管理质量需求矩阵（对象×维度×指标+优先级），以便明确质量管理目标和范围。
- **US-Q03** 作为质量负责人，我希望管理质量规则库、剖析和检查执行，以便发现和验证数据质量问题。
- **US-Q04** 作为质量负责人，我希望独立管理质量问题并驱动闭环（发现→确认→分发→整改→复检→关闭），以便跟踪问题至关闭。
- **US-Q05** 作为质量整改人员，我希望接收分发的问题并按职责分离要求整改和复检，以便规范完成整改。
- **US-Q06** 作为质量负责人，我希望分析质量趋势和根因，以便制定改进措施。
- **US-Q07** 作为质量负责人，我希望形成版本化质量改进报告并跟踪效果，以便持续改进。

### 跨模块

- **US-X01** 作为治理人员，我希望元数据对象引用明确的数据标准版本和最近稽核结果，以便查看规范性但不复制标准正文。

## 验收标准 · Acceptance Criteria

### 治理中心

- **AC-G01** 治理大盘应展示组织健康度、制度覆盖、文化成效和治理问题四象限概览，并提供个人工作台待办驱动。
- **AC-G02** 治理组织页应支持三级组织架构（决策/管理/执行）、岗位职责定义，并展示认责总览（覆盖率、按业务部门统计、异常清单、业务部门量化考核）。
- **AC-G03** 认责字段在元数据对象详情编辑并回写；治理组织面通过对象 ID 聚合认责总览，不重复维护认责事实。
- **AC-G04** 制度管理应支持政策/办法/细则三层文档库、版本管理、起草审核发布流程，并记录执行监控批次（通过/部分通过/未执行/偏差 + 符合度评分 + 偏差明细 + 整改）。
- **AC-G05** 文化管理应支持文化价值观、宣贯培训、标杆案例记录，并展示文化成效量化指标（L4）。
- **AC-G06** 治理大盘与个人工作台 KPI 摘要引用 `/metrics/governance`，不在本 feature 重复计算。

### 元数据与血缘

- **AC-M01** 元数据检索页应支持对象检索、按元模型对象类型筛选、技术/业务属性（按元模型属性集渲染）、认责字段编辑、更新时间和血缘详情。
- **AC-M02** 元模型配置页应支持对象类型、属性集（必填/采集/值域约束）、关系类型（源/目标/方向/影响权重）、采集规则（来源/方式/频率/字段映射 + 采集任务状态）的 CRUD。
- **AC-M03** 元数据质量评价页应支持三维评分（准确性/完整性/时效性，由元模型驱动）、评价批次（不可覆盖，引用元模型版本）、趋势、问题闭环（联动认责管理者）。
- **AC-M04** 血缘关系应能表达数据源、任务、湖表、指标和数据服务的上下游依赖，并展示影响范围；L4 AI 血缘追踪为 mock 建议待确认。
- **AC-M05** 元数据质量评价（DCMM 8.4）与数据质量（DCMM 11）分属不同能力域，评价对象和指标维度不同，不混合管理。
- **AC-M06** 元数据对象应能引用企业标准 ID、版本 ID、本体概念 ID 和最近稽核摘要，并跳转目标 `/data-standard/*` 页面。
- **AC-M07** 元数据管理报告应支持版本化、量化指标（采集覆盖率/质量分/血缘完整率），引用 `/metrics/architecture` KPI 不重复计算。

### 数据质量

- **AC-Q01** 质量概览页应展示综合可信度、五维评分、批次趋势和问题闭环漏斗。
- **AC-Q02** 质量需求矩阵应支持对象×维度×指标+优先级+信息环境上下文，并预留 L4 AI 需求矩阵识别建议。
- **AC-Q03** 质量规则页应支持规则 CRUD、启停、剖析、检查执行批次；规则失败生成质量问题跳转问题工作台。
- **AC-Q04** 质量问题工作台应支持问题独立管理（绑定对象/规则/维度/严重等级），闭环状态机（发现→确认→分发→整改→复检→关闭），职责分离（确认人≠处置人≠复核人，处置人不得自行关闭）。
- **AC-Q05** 质量问题分发对象自动取自元数据对象认责管理者（D2 联动）。
- **AC-Q06** 质量分析页应支持跨批次趋势、根因聚类、对比分析。
- **AC-Q07** 质量改进报告应版本化，包含趋势+根因+措施+效果复评，引用 `/metrics/quality` KPI 不重复计算。

### 跨模块

- **AC-X01** 治理状态可被数据资产目录、调度监控和数据服务发布流程引用。
- **AC-X02** `/data-governance/standards` 不作为当前或兼容路由；本 feature 不维护业务术语、主数据、参考数据、数据元或指标字典正文。

## 范围 · Scope

### 治理中心（DCMM 7 数据治理域）

- 治理大盘 + 个人工作台
- 治理组织（三级架构、岗位职责、认责总览、业务部门量化考核）
- 制度建设（三层文档库、版本、执行监控 mock 批次、符合度评分、偏差整改）
- 文化建设（价值观、宣贯培训、标杆案例、成效量化指标）

### 元数据与血缘（DCMM 8.4 元数据管理）

- 元模型配置（对象类型、属性集、关系类型、采集规则）
- 元数据检索、对象详情（按元模型渲染 + 认责字段编辑）和血缘（按关系类型 + 影响分析）
- 元数据质量评价（三维评分、批次、趋势、问题闭环、L4 AI 辅助）
- 元数据管理报告（版本化、量化指标）

### 数据质量（DCMM 11 数据质量域）

- 质量概览（综合可信度、维度评分、趋势、问题闭环漏斗）
- 质量需求矩阵
- 质量规则库、剖析、检查执行
- 质量问题工作台（独立对象、闭环状态机、职责分离、认责联动）
- 质量分析（趋势、根因、对比）
- 质量改进报告（版本化、效果跟踪）

### 跨模块

- 数据标准稳定引用和稽核摘要
- 治理状态引用（资产目录、调度监控、服务发布）

## 非目标 · Out of Scope

- 真实扫描器、采集器、探查器、规则执行引擎、血缘采集器和制度执行引擎
- 真实 AI 执行（所有 AI 辅助为 mock 建议待确认）
- 业务术语、本体模型、主数据、参考数据、数据元标准、指标字典及其审批；见独立 [`data-standard`](../data-standard/README.md) 规格
- 数据治理组织流程和外部审批系统
- 用前端评分替代生产质量结论
- L4 量化指标的重复计算（统一引用 `/metrics/*`）
