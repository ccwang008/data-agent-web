# Data Lake · Requirements

## 目标用户 · Personas

| 角色 | 场景 | 期望产出 |
|---|---|---|
| 数据工程师 | 管理湖表、Schema 和版本 | 可演进、可回溯的数据结构 |
| 数据治理人员 | 查看数据分层、生命周期和责任 | 可解释、可运营的存储资产 |
| 平台运维人员 | 查看容量和冷热分布 | 可预测、可控制的存储成本 |

## 用户故事 · User Stories

- **US-01** 作为数据工程师，我希望统一管理表、文件、图片、视频、日志和文档，以便用同一平台发现和管理数据。
- **US-02** 作为数据工程师，我希望创建湖表并管理 Schema、版本和事务属性，以便安全演进数据模型。
- **US-03** 作为运维人员，我希望看到分层容量、增长趋势和生命周期策略，以便执行冷热分层、归档和清理。

## 验收标准 · Acceptance Criteria

- **AC-01** 存储页面应区分结构化和非结构化对象，并展示类型、位置、大小、层级、状态和更新时间。
- **AC-02** 湖表页面应支持表建模、Schema 字段、版本、负责人和事务能力的查看/编辑交互。
- **AC-03** 容量页面应展示各存储层的容量、占用、增长和对象数量，并能配置冷热、归档、清理策略。
- **AC-04** 生命周期策略应包含保留期、目标层级、归档动作和清理动作，并对危险操作提供确认。
- **AC-05** 前端 mock 数据模型应预留 `schemaVersion`、`storageTier`、`retentionPolicyId` 和 `lineageId` 等关联字段。

## 范围 · Scope

- 统一数据存储对象列表和详情
- 湖表建模、Schema、版本和 ACID 能力展示
- 数据分层、容量统计和生命周期策略

## 非目标 · Out of Scope

- 真实对象存储、湖表格式和事务引擎实现
- 真实数据迁移、归档、压缩和删除执行
- 生产级成本计费系统
