# 大数数据平台 · 需求说明书

> 用途说明：本文件是对外需求沟通文档，用于向业务方、评审方和协作团队统一说明平台建设需求。本文件不参与 spec-driven 开发流程；开发实现的依据以 `specs/features/*/requirements.md` 与 `AGENTS.md` 为准。

---

## 第一部分 · 原始需求

### 1.1 产品背景与定位

大数数据平台是面向企业的数据资产与 AI 数据服务平台，覆盖数据集成、数据湖、数据治理、数据标准、数据开发、调度引擎、运维监控、数据安全和 DCMM 量化管理。平台的核心目标不是“把数据存起来”，而是让数据可发现、可理解、可授权、可调用、可追踪，帮助企业把分散的数据转化为可运营的数据资产。

当前交付物为本地全栈原型：业务数据和执行结果保持 mock 语义，但可变业务状态（列表、详情、增删改查、运行状态、调度结果、质量评分、服务调用、安全策略和监控指标）统一持久化到本地 SQLite，不依赖真实数据源、真实执行引擎或生产级服务。

### 1.2 目标用户

| 角色 | 核心关切 |
|---|---|
| 数据工程师 | 数据源接入、数据湖表、ETL/SQL/Notebook、流水线编排 |
| 数据治理人员 | 元数据、血缘、数据质量、数据标准和数据价值 |
| 数据标准负责人 | 业务术语、主数据、参考数据、数据元、指标字典的企业级归并 |
| 数据资产运营人员 | 资产目录、权属、估值、产品运营、流通审批与使用审计 |
| 数据安全负责人 | 合规、分类分级、防护、出境评估、审计与事件响应 |
| 运维管理员 | 任务、链路、质量、计算资源、安全和审计 |
| 业务用户 | 资产检索、申请授权、指标和数据服务调用 |
| 量化管理者 | DCMM 九域能力态势、KPI 跟踪与改进闭环 |
| AI 应用开发者 | 通过数据服务使用可信数据 |

### 1.3 建设目标：DCMM 4 级量化管理就绪度

本系统以 **GB/T 36073—2025《数据管理能力成熟度评估模型》DCMM 4 级（量化管理级）** 作为产品实现和验收参考，以提升组织的 DCMM 第 4 级就绪度和举证能力为建设目标。

- 具备 DCMM 3 级要求的组织级统一制度、职责、流程和管理能力，并在此基础上实现 4 级要求的量化管理。
- 为关键管理过程设置可计算的量化指标，支持目标值、实际值、趋势、异常和改进措施的持续跟踪。
- 定期形成管理评价、效益评价和分析报告，使评价依据、数据来源、计算过程和结果可追溯。
- 数据资产能力对照标准第 9 章建设，数据标准能力对照标准第 10 章建设，数据安全能力对照标准第 12 章建设。
- 重要业务对象应具备稳定标识、责任主体、状态、版本、时间、来源、审批记录、变更历史和审计信息。

> 重要约束：软件功能不自动构成认证结论或通过保证。当前 SQLite 持久化 mock 用于验证产品能力和证据结构，不代表系统已经通过认证；正式评估前仍需接入真实组织制度、业务数据、执行系统和审计材料。页面不得出现“已达到 DCMM 4 级”、认证预测或综合成熟度得分。

### 1.5 非目标与边界

以下内容不在当前交付范围：

- 真实数据库、消息队列、对象存储、API 网关、CDC 引擎、Notebook 内核、调度执行器或计算集群连接。
- 生产级 IAM、KMS、DLP、加密、脱敏、水印、异常检测或安全态势引擎。
- 真实监管申报、标准合同备案、认证申请、通知发送或外部审计服务。
- 真实 DCMM 认证结论、通过概率或替代外部评估。
- 通用工作流设计器、任意公式执行器、复杂事件编排或多租户。
- 在 SQLite 或浏览器中保存密码、token、私钥、完整连接串或其他真实敏感数据。
- “测试模块”不是产品域，不新增测试中心、测试菜单或面向用户的测试页面。

### 1.6 技术与交付约束

- 技术栈：React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui（Classic Light SaaS 主题）+ Zustand + React Router v6 + react-i18next + @xyflow/react + Node 22 `node:sqlite`。
- 可变业务状态统一通过 `useSqliteState` 持久化到本地 SQLite；业务页面不得直接调用外部 `fetch`、`axios` 或真实数据源。
- mock 数据应覆盖正常、空数据、加载中、失败、运行中、成功和已停止等产品状态，但不代表真实生产执行结果。
- 视觉采用 Classic Light SaaS：浅色工作区、白色面板、蓝色主色、紧凑表格和清晰状态反馈；避免紫色渐变、营销页 hero 和过大圆角。
- 页面必须先根据用户的核心任务、业务对象关系和决策路径设计信息架构，不得以“顶部通用指标卡 + 筛选栏 + 下方 CRUD 列表/表格”作为跨页面默认模板。

## 第二部分 · 各需求模块详细说明

### 模块 1 · 平台入口（产品矩阵 + 行业方案）

**模块定位**
统一的产品发现入口和行业能力展示，让用户快速理解平台能力并进入对应工作台。

**目标用户**：平台用户、官网访客。

**核心功能需求**

产品矩阵首页（`/`）：
- 按业务应用层、AI 平台、数据平台、基础设施层分层浏览产品。
- 点击产品类型后只展示对应产品卡片，并显示数量。
- 产品卡片展示名称、描述、能力摘要和进入入口；Data Stack 的八个产品域能力可直接进入对应工作台。
- 支持按产品名称、英文名、描述和能力名称搜索；无结果时展示空状态。
- 全部内容使用本地 mock 配置，不请求真实 API。

行业解决方案（`/solutions`）：
- 展示独立的行业解决方案页面，不显示通用工作台侧栏和顶栏。
- 至少展示金融、工业、交通、能源、政务、教育、医疗七个行业入口，使用本地图片素材。
- 点击行业入口仅切换标题、描述、指标和标签，不请求真实 API。
- 顶部可返回产品矩阵首页。

**当前实现状态**：产品矩阵首页和行业方案页已实现 SQLite 持久化 mock。

### 模块 2 · 量化看板

**原始需求**

> 建设目标：为 DCMM 九大能力域建立可量化的 KPI 指标，并通过看板实时监控。

| 能力域 | 建议量化指标示例 |
|---|---|
| 数据战略 | 数据战略目标达成率、战略实施偏差率 |
| 数据治理 | 治理会议频次、问题闭环率、数据管家覆盖率 |
| 数据架构 | 元数据自动采集覆盖率、模型规范评审通过率 |
| 数据资产 | 资产目录完整率、资产使用率、资产价值增长率 |
| 数据标准 | 关键标准落标率、业务术语覆盖率、指标口径一致率 |
| 数据质量 | 问题发现数、平均修复时长、闭环率、质量规则覆盖率 |
| 数据安全 | 分类分级覆盖率、审计日志完整性、安全事件响应时长 |
| 数据生存周期 | 数据归档率、SLA 达标率 |
| 数据应用流通 | API 调用量、数据服务满意度、外部数据接入数 |

**模块定位**
为量化管理者提供组织级 DCMM 九域态势，为能力域负责人提供可解释、可追溯、可改进的 KPI 管理工作台。

**目标用户**：量化管理者、指标管理员、能力域负责人、DCMM 建设人员。

**核心功能需求**

- 一个综合看板和九个能力域看板，共十个路由化 Tab：数据战略、数据治理、数据架构、数据资产、数据标准、数据质量、数据安全、数据生命周期、数据应用流通。
- 25 项核心 KPI 分布在九域，每项具备口径、目标、实际值、状态、趋势、新鲜度、责任人和证据引用。
- 33 个能力项覆盖矩阵，展示能力项与核心/诊断指标、观测值、证据和改进事项的关联；待建设项不记为零分。
- 各看板独立配置当前、日、周、月视图；日更语义；日/周/月冻结快照；季度报告。历史快照不用最新口径重算。
- 目标版本管理：调整目标创建新版本，历史观测继续引用旧目标。
- 人工指标填报要求统计范围、数据时间和证据；从风险项创建改进事项，同一 KPI 与周期不得出现两个未关闭事项。
- 关闭改进事项记录处理结果、效果证据、关闭人和时间，无审批流程。
- 综合看板展示九域达标率与健康状态、核心 KPI 风险清单及跨域改进优先级。

**25 项核心 KPI 摘要**

| 能力域 | 核心 KPI | 评价方向 | 首期组织目标 |
|---|---|---|---|
| 数据战略 | 数据战略目标达成率 / 战略实施偏差率 | 越高/越低 | ≥90% / ≤10% |
| 数据治理 | 治理会议频次 / 治理问题闭环率 / 数据管家覆盖率 | 区间/越高 | 每月 1–2 次 / ≥95% / ≥90% |
| 数据架构 | 元数据自动采集覆盖率 / 模型规范评审通过率 | 越高 | ≥95% / ≥90% |
| 数据资产 | 资产目录完整率 / 资产使用率 / 资产价值增长率 | 越高/趋势 | ≥98% / ≥60% / 同比≥10% |
| 数据标准 | 关键标准落标率 / 业务术语覆盖率 / 指标口径一致率 | 越高 | ≥95% / ≥90% / ≥98% |
| 数据质量 | 质量问题发现数 / 平均修复时长 / 闭环率 / 规则覆盖率 | 趋势/越低/越高 | ≤48h / ≥95% / ≥95% |
| 数据安全 | 分类分级覆盖率 / 审计日志完整性 / 事件响应时长 | 越高/越低 | ≥95% / ≥99.9% / 按 S1–S4 SLA |
| 数据生命周期 | 数据归档率 / 数据 SLA 达标率 | 越高 | ≥95% / ≥99% |
| 数据应用流通 | API 调用量 / 数据服务满意度 / 外部数据接入数 | 趋势/越高/区间 | ≥85% |

> 以上阈值为首期组织管理默认值，不是 GB/T 36073—2025 规定的固定认证阈值。

**关键约束**
- 看板不得输出 DCMM 成熟度评分、认证结论或通过概率。
- 数据安全域事件必须按 S1–S4 分层评价，不得用跨等级平均掩盖严重事件超时。
- 数据标准来源事实由数据标准域维护，本看板不复制可编辑标准、稽核或 AI 决策正文。

**当前实现状态**：综合看板 + 九域看板与 SQLite 持久化 mock 已实现。

### 模块 3 · 数据集成

**模块定位**
把外部数据接入平台并稳定搬运，支持跨域和对外数据交换。

**目标用户**：数据工程师、数据集成开发者、数据交换管理员、平台运维人员。

**核心功能需求**

数据源管理：
- 按类型管理数据源（数据库、文件、消息队列、API），支持新增、查看、编辑、删除、连接测试和状态管理。
- 列表显示名称、类型、连接状态、负责人和更新时间，支持搜索和筛选。
- 创建/编辑时根据类型展示对应配置字段，凭证不得明文展示。

数据同步：
- 支持全量（full）、增量（incremental）、CDC、实时（realtime）四类同步模式。
- 配置源端、目标端、字段映射、调度策略、失败重试；展示状态、进度和最近运行结果。

共享交换：
- 覆盖 API、文件、库表、消息四类交换方式。
- 保留交换状态、失败原因和审计关联；支持审批、传输状态、失败重试和审计。

**关键约束**：不实现真实数据库、消息队列、对象存储、API 网关和文件传输执行器；不保管凭证、密钥和连接串。

**当前实现状态**：SQLite 持久化 mock 已实现。

### 模块 4 · 数据湖

**模块定位**
统一管理企业结构化和非结构化数据，提供存储、湖表建模、分层容量和生命周期能力。

**目标用户**：数据工程师、数据治理人员、平台运维人员。

**核心功能需求**

统一数据存储：
- 统一纳管表、文件、图片、视频、日志、文档等对象。
- 区分结构化和非结构化，展示类型、位置、大小、层级、状态和更新时间。

湖表管理：
- 支持表建模、Schema 字段、版本、负责人和 ACID 事务能力的查看/编辑。
- Schema 演进可回溯，不覆盖历史版本。

分层与容量：
- 展示各存储层的容量、占用、增长和对象数量。
- 生命周期策略包含保留期、目标层级、归档动作和清理动作，危险操作需确认。

**关键约束**：不实现真实对象存储、湖表格式和事务引擎；不执行真实数据迁移、归档、压缩和删除。

**当前实现状态**：SQLite 持久化 mock 已实现。

### 模块 5 · 数据标准

**原始需求**

> 数据标准统一管理平台

- 企业级业务术语库（复用 plugins.ontology 和语义层）
- 指标字典统一管理（含口径定义、计算逻辑、数据来源、责任人）
- 标准落标自动稽核
- 跨部门指标一致性比对

**模块定位**
建立企业级统一数据标准管理能力，将分散在项目中的业务术语、主数据规范、参考数据、数据元和指标口径归并为可审批、可引用、可稽核、可量化和可追溯的组织级标准。产品以提升 GB/T 36073—2025 第 10 章五项能力的 DCMM 第 4 级就绪度为目标，不输出认证结论。

**目标用户**：数据标准负责人、标准维护人、业务数据管家、主数据管理员、指标管理员、量化管理者。

**核心功能需求**

- **企业标准候选与归并**：项目级定义导入后进入候选池，保留来源；AI 自动识别重复、同义、可合并和冲突候选；经业务数据管家复核、数据标准负责人批准后生成企业级稳定 ID 和不可覆盖版本；项目对象切换到企业标准版本并通过稽核后才标记为已落标。
- **业务术语与本体模型**：企业级业务术语库记录名称、定义、缩写、同义词、使用场景、责任归属、版本和状态；批准发布前必须绑定唯一有效本体概念；同义词共享概念身份不重复创建概念。
- **主数据**：定义实体范围、属性、唯一标识、查重规则、权威数据源；AI 自动识别重复、推荐属性保留值；满足策略且无关键冲突时可自动合并，关键冲突由数据管家裁决；自动与人工裁决均记录来源、置信度、策略/模型版本、前后值和权威记录版本。
- **参考数据**：管理分类、目录、代码集、代码值、层级、有效期和版本；组织级与部门/系统代码值的映射矩阵、差异比较、发布和订阅分发；AI 自动映射，准确率低于目标时暂停自动发布。
- **数据元标准**：数据元具有稳定 ID，记录类型、长度、格式、计量单位、值域和约束；关联批准业务术语、本体概念和参考数据集；AI 识别字段候选并执行自动落标和约束稽核。
- **指标字典与语义层**：支持指标体系和原子/派生/复合指标关系；企业指标稳定 ID，记录口径、公式、过滤条件、粒度、周期、维度、来源、责任人、版本和状态；数据标准域权威维护语义层指标模型；AI 自动进行口径比对，结果分为一致、受控变体、冲突和未知。
- **审批、版本与证据**：AI 生成候选，标准维护人编辑提交，业务数据管家复核，数据标准负责人批准发布或废止；已发布定义不可覆盖，修订生成新版本；五项能力分别登记国家/行业标准参与项目证据，缺失时显示证据缺口。
- **标准落标自动稽核**：应落标对象由治理范围明确；结果为通过、失败、未知、不适用；每次稽核形成不可覆盖批次，冻结标准、对象、规则和 AI 模型版本；同一对象+标准版本+规则最多一个未关闭整改问题，重复失败追加证据。
- **AI 审计与熔断**：AI 判定记录模型/版本、策略版本、证据、置信度、依据摘要、执行结果和复核结果；低于策略阈值进入未知/待复核；抽样准确率低于目标时自动暂停对应自动化。

**三项核心 KPI**

| KPI | 公式 | 默认目标 |
|---|---|---|
| 关键标准落标率 | 通过稽核的应落标关键对象 ÷ 全部应落标关键对象（失败和未知留在分母） | ≥95% |
| 业务术语覆盖率 | 具有批准术语定义的关键业务概念 ÷ 应纳入管理的关键业务概念 | ≥90% |
| 指标口径一致率 | 一致组与受控变体组 ÷ 全部应比对组（冲突和未知留在分母） | ≥98% |

另有 26 项必备诊断指标覆盖业务术语、主数据、参考数据、数据元标准、指标字典和跨能力版本归并，默认目标 80%–100% 不等。

**关键约束**
- 数据标准不作为数据资产类型，本期不建设标准资产发布、申请、授权、下发或流通流程。
- 不实现真实主数据平台、数据库扫描器、参考数据服务、语义查询引擎或 AI 模型服务。
- 页面不得以软件功能自动宣称组织达到 DCMM 第 4 级。

**当前实现状态**：五个工作台（业务术语、主数据、参考数据、数据元标准、指标字典）与 SQLite mock 已实现。

### 模块 6 · 数据治理

**原始需求**

> 数据治理沟通与协作平台

- 治理会议管理（议题、纪要、决议跟踪）
- 数据问题工单系统（与质量闭环打通）
- 数据资产变更通知和评审流程
- 知识沉淀和最佳实践库

**模块定位**
基于 GB/T 36073—2025 DCMM 第 4 级要求，覆盖治理中心（DCMM 7 数据治理域）、元数据与血缘（DCMM 8.4 元数据管理）、数据质量（DCMM 11 数据质量域）。数据标准正文不在本模块维护。

**目标用户**：数据治理负责人、数据治理人员、元数据管理员、质量负责人、质量整改人员、数据资产运营人员。

**核心功能需求**

治理中心：
- 治理大盘展示组织健康度、制度覆盖、文化成效和治理问题四象限概览，并提供个人工作台待办驱动。
- 治理组织支持三级架构（决策/管理/执行）、岗位职责定义，展示认责总览（覆盖率、按业务部门统计、异常清单、业务部门量化考核）。
- 制度管理支持政策/办法/细则三层文档库、版本管理、起草审核发布流程，记录执行监控批次（通过/部分通过/未执行/偏差 + 符合度评分 + 偏差明细 + 整改）。
- 文化管理支持价值观、宣贯培训、标杆案例记录，展示文化成效量化指标。

元数据与血缘：
- 元数据检索支持对象检索、按元模型对象类型筛选、技术/业务属性渲染、认责字段编辑、血缘详情。
- 元模型配置支持对象类型、属性集（必填/采集/值域约束）、关系类型（源/目标/方向/影响权重）、采集规则（来源/方式/频率/字段映射 + 采集任务状态）。
- 元数据质量评价按三维评分（准确性/完整性/时效性，由元模型驱动），形成不可覆盖评价批次、趋势和问题闭环。
- 血缘表达数据源、任务、湖表、指标和数据服务的上下游依赖和影响范围。
- 元数据对象引用企业标准 ID、版本 ID、本体概念 ID 和最近稽核摘要，跳转数据标准页面。
- 元数据管理报告版本化，引用 `/metrics/architecture` KPI 不重复计算。

数据质量：
- 质量概览展示综合可信度、五维评分、批次趋势和问题闭环漏斗。
- 质量需求矩阵支持对象×维度×指标+优先级+信息环境上下文。
- 质量规则库支持 CRUD、启停、剖析、检查执行批次；规则失败生成质量问题跳转问题工作台。
- 质量问题工作台支持独立管理（绑定对象/规则/维度/严重等级），闭环状态机（发现→确认→分发→整改→复检→关闭），职责分离（确认人≠处置人≠复核人，处置人不得自行关闭）。
- 质量问题分发对象自动取自元数据对象认责管理者。
- 质量分析支持跨批次趋势、根因聚类、对比分析。
- 质量改进报告版本化，包含趋势+根因+措施+效果复评，引用 `/metrics/quality` KPI 不重复计算。

**关键约束**
- 元数据质量评价（DCMM 8.4）与数据质量（DCMM 11）分属不同能力域，评价对象和指标维度不同，不混合管理。
- 不实现真实扫描器、采集器、探查器、规则执行引擎、血缘采集器；所有 AI 辅助为 mock 建议待确认。
- L4 量化指标统一引用 `/metrics/*`，不在本模块重复计算。

**当前实现状态**：治理中心（4 页）、元数据（4 页）、数据质量（6 页）共 14 页 SQLite 持久化 mock 已实现。

### 模块 7 · 数据开发

**模块定位**
为数据工程师、数仓开发者、数据分析师和算法工程师提供三种互补的专业开发工作台：可视化 ETL、SQL 开发、Notebook。三种方式共享任务身份、版本、发布、运行、审计和血缘契约，但拥有独立的编辑器和交互模型。

**目标用户**：数据工程师、SQL 开发者、数据分析师、算法工程师。

**共享需求**

- 统一身份与状态：每个对象具备 id、name、owner、status、currentVersion、publishedVersion 等；状态分层管理（编辑/生命周期/执行/校验）。
- 版本与发布：草稿可自动保存，发布生成不可变版本；调度引擎通过 `artifactType + artifactId + version` 引用开发任务；已发布版本不能原地修改。
- 运行、日志与血缘：统一记录 runId、版本、触发方式、状态、耗时、日志和结果摘要；记录输入/输出对象引用；错误反馈定位到 ETL 节点、SQL 行列或 Notebook 单元格。

**可视化 ETL**
- 画布编排：左侧节点库、中央画布、右侧属性面板、底部运行面板；支持拖拽、连线、缩放、平移、撤销重做。
- 节点类型：输入（数据表/文件/数据集）、转换（字段选择/过滤/派生/类型转换/关联/聚合/排序/去重/合并）、输出（湖表/数据集/临时结果）。
- 节点配置与字段映射：支持自动匹配、手动调整、类型冲突和缺失字段提示。
- 校验、预览与试运行：支持节点级和全流程校验；运行当前节点/运行至当前/运行下游/运行全流程；失败后从失败节点重新运行。

**SQL 开发**
- 编辑器：左侧数据目录、中间多标签代码编辑区、底部结果面板、右侧参数/版本面板；支持语法高亮、行号、括号匹配、代码折叠、查找替换、格式化。
- 参数与安全：支持字符串/数字/日期/布尔参数；高风险 DDL/DML 显示风险标识；试运行可临时覆盖参数。
- 校验、执行与结果：支持当前语句/选中 SQL/完整脚本执行；错误包含行号、列号、原因；结果面板含数据结果、日志、错误和执行计划。
- 版本与发布：版本保存 SQL、参数、数据源上下文、输出声明；支持历史版本比较和恢复为新草稿。

**Notebook**
- 单元格编辑：支持 Markdown、SQL、Python、R、参数单元格；支持增删、复制、移动、类型切换；Markdown 标题自动形成大纲。
- 运行时与执行：支持 Python、SQL+Python、R mock 运行时；内核状态（未启动/启动中/空闲/忙碌/失败/已停止）；运行当前单元/上方/下方/全部/停止/重启内核；修改已执行单元标记后续为可能过期。
- 输出、变量与检查点：输出含文本、表格、日志、图片占位、指标卡、错误堆栈；变量面板展示名称、类型、摘要；手动检查点保存代码、参数、运行时和输出快照。
- 发布与可复现性：发布前必须执行“从干净内核运行全部”校验；存在过期结果、隐藏状态依赖或完整运行失败时禁止发布。

**关键约束**：不实现真实 ETL/SQL/Python/R 执行，不启动 GPU 资源或管理计算集群；不重复建设调度 DAG、运维监控或资产审批页面。

**当前实现状态**：ETL/SQL/Notebook 专业工作台 P0 与 SQLite mock 已实现。

### 模块 8 · 数据资产

**原始需求**

> 建设目标：建立企业级数据资产目录，实现数据资产从确权到运营的全生命周期管理。

核心功能需求：

- 数据资产目录：自动扫描并编目数据库表、API、报告、模型等数据资产
- 权属登记：记录数据持有权、使用权、经营权，支持版本追踪和变更历史
- 价值评估：支持成本法/收益法/市场法定价模型，记录评估过程和数据来源
- 资产运营：数据产品的发布、审批、授权、使用统计，对外提供 API 或下载服务
- 资产使用审计：记录每次数据访问的来源、目的、结果

**模块定位**
建立企业级数据资产目录，实现数据资产从确权到运营的全生命周期管理，参考 GB/T 36073—2025 DCMM 4 级要求强化量化管理、过程留痕、证据追溯和持续改进。数据标准不作为资产类型。

**目标用户**：资产负责人、数据持有主体、权属确认人、评估人员、评估复核人、运营人员、安全审批人、使用方、审计人员。

**核心功能需求**

资产详情并列展示目录、权属、评估、运营四组独立状态，不以一个总状态混合不同管理流程：
- 目录：正常、来源异常、待退役、已退役、已归档
- 权属：待登记、待确认、已确权、已失效
- 评估：未评估、进行中、待复核、有效、待替代、已过期
- 运营：无产品、草稿、审批中、运营中、已暂停、已下线

**FR-01 数据资产目录**
- 自动扫描并编目数据库表、API、报告、模型等数据资产；数据标准不进入本目录。
- 资产添加采用“自动扫描为主、从数据源直接添加和人工补录为辅”。
- 保留数据表、数据集、指标、标签、数据服务、JSON、XML、日志、消息数据、文档、图片、视频、音频、知识资料和“模型”类型。
- 每项资产设置一名资产负责人，负责人变更不生成权属版本。
- 平台生成永久资产 ID，名称/位置变化时保持不变。
- 资产及字段通过稳定 ID 引用数据安全模块中当前生效的分类分级记录，不在资产模块重复维护。
- 支持手动和周期扫描，默认增量；扫描状态为待运行/运行中/成功/部分成功/失败/已取消；同批次重复执行不重复创建资产。
- 退役前检查已发布产品、有效授权和未关闭异常；已退役/归档资产只读查看，不得新增授权或发布产品。

**FR-02 权属登记**
- 记录数据持有权、使用权和经营权及其主体、范围、有效期。
- 一个资产可同时登记多个持有/使用/经营主体，每条权属关系分别设置数据范围、用途、有效期、登记依据和状态。
- 经营权到期前 30/7/1 天提醒；到期或撤销时立即暂停覆盖的数据产品。
- 权属版本经审批生效后不可覆盖；采用“登记人提交 → 权属主体确认”固定流程。
- 本期不设计独占权、上下级权利链或自动权属冲突推断。

**FR-03 价值评估**
- 支持成本法（重置成本 - 功能性贬值 - 经济性贬值，应用质量与合规调整系数）、收益法（预测期增量净收益及终值折现）、市场法（可比案例调整加权）。
- 首期使用固定计算模板和可配置参数，不建设任意公式编辑器；评估人员不得直接覆盖计算结果。
- 每份评估绑定资产 ID、资产版本、评估基准日、有效期、当时权属版本和安全分类版本；后续资产版本变化不修改原评估快照。
- 评估状态：草稿、计算中、待复核、已生效、已驳回、已过期、已被替代。
- 有效估值默认有效期 12 个月；质量/合规恶化、成本变化超 20%、收益预测变化超 20% 或可比案例失效时提前触发重评。

**FR-04 资产运营**
- 数据产品发布、审批、授权和使用统计；一个产品可关联多个资产。
- 对外提供 API 或下载服务；每次调用关联使用方、授权、服务版本和资产版本。
- API 授权范围可细化为字段、行范围或业务区域；超范围、过期、超配额或产品暂停时拒绝调用并生成审计记录。
- 下载授权生成一次性或限次下载任务，可配置有效期、最大次数、数据范围、文件格式和脱敏策略。
- 发布审批（运营提交 → 资产负责人确认 → 安全审批人审核）与使用授权（使用方提交 → 资产负责人审批，敏感/对外追加安全审批）是两个独立但关联的流程。
- 使用授权必须选择标准目的；调用/下载继承授权目的，目的不一致时拒绝访问。
- 正式发布前必须同时满足：关联资产已确权、有效经营权覆盖、存在有效估值、服务版本完整、审批通过。

**FR-04A 资产流通申请**
- 为目录资产提供直接流通入口，补足“不先包装成数据产品也需要受控使用”的场景。
- 一张申请固定关联一个资产 ID 和资产版本，记录申请人、主体、消费系统、使用目的、范围、交付方式、有效期。
- 流程：提交申请 → 资产负责人审批 → 条件性安全审批 → 对接配置与联调 → 使用跟踪。
- 审批通过后生成资产对接任务，按 API/文件下载/在线查询显示不同脱敏配置。
- 流通状态：草稿、待负责人审批、待安全审批、待对接、对接中、使用中、已退回、已驳回、对接失败、已暂停。

**FR-05 资产使用审计**
- 记录每次数据访问的来源、目的和结果；访问来源结构化记录使用方主体、来源系统、访问渠道、用户/服务账号 ID、请求追踪 ID。
- API 每次成功/失败/拒绝/超时均生成审计记录；文件生成和下载、在线查询、数据预览在实际读取数据时生成审计记录。
- 搜索目录、查看资产详情和查看审批单不属于数据访问，记录为普通操作日志。
- 审计记录不得保存 API 原始响应、下载文件内容、密码、令牌或真实敏感数据。
- 通过超配额、连续失败、越权字段和异常下载频率等规则识别访问异常；异常状态：待研判、已确认异常、已排除、整改中、待复核、已关闭。
- 审计记录默认保留 3 年，保留期内不得修改或业务删除；到期先归档，存在未关闭异常时禁止清理。

**DCMM 4 量化目标（首期默认值，可调整）**

| 指标 | 默认目标 |
|---|---|
| 目录编目完整率 | ≥98% |
| 元数据准确率 | ≥97% |
| 扫描更新及时率 | ≥95% |
| 权属登记完整率 | ≥98% |
| 权属变更按期完成率 | ≥95% |

### 模块 11 · 数据安全

**原始需求**

> 建设目标：将安全能力从“有防护”升级为“能举证”。

核心功能需求：

- 数据分类分级引擎：基于语义理解自动识别 PII、重要数据、敏感商业数据，输出分类分级报告
- 安全审计报告自动生成：按 DCMM 审计要求，一键生成涵盖数据访问、流转、交换行为的审计报告
- 数据出境合规评估：对跨境数据传输场景提供合规检查清单和风险评估
- 安全事件响应 SOP 和记录系统

**模块定位**
将数据安全能力从“有防护”升级为“能举证”，建立面向数据安全负责人、法务合规、独立审计和事件响应人员的合规与证据工作台。产品覆盖 GB/T 36073—2025 第 12 章的数据合规管理、数据安全防护和数据安全审计，按第 4 级量化管理级要求提供量化指标、AI 辅助、证据追溯和持续改进。

**目标用户**：数据安全负责人、数据负责人、法务合规人员、审计人员、事件响应人员、业务申请人/资产运营人员。

**职责分离原则**：数据负责人不批准自己提交的重要/核心数据结论；审计人员不修改来源域原始事件，不负责整改后自行关闭；事件响应人员不独立复核自己处置的事件；业务申请人不审批自己的申请。

**核心功能需求**

**FR-01 安全总览**
- 以安全驾驶舱展示合规、防护、审计三域的 DCMM 第 4 级就绪度。
- 展示量化指标、趋势、证据缺口、逾期整改、高风险出境场景和重大事件待办。
- 控制项状态为“不适用、证据不足、待整改、基本就绪”，不提供“已认证”状态。

**FR-02 数据合规管理**
- 合规规则包记录法域、权威来源、版本、生效/失效日期和替代关系；首版使用中国大陆合规基线。
- 合规清单把规则要求映射到责任人、适用对象、证据、检查状态和整改。
- 合规审查支持新项目、数据处理活动和专项审查；个人信息管理记录处理目的、必要性、依据和接收方证据；重要数据管理维护候选、生效记录和申报/保护证据。
- 外部合规评估只登记机构、范围、期间、报告引用，不模拟外部评估结论。

**FR-03 数据分类分级引擎**
- 以数据项为最小判定对象（结构化字段、JSON/XML 路径、API 字段、非结构化敏感区域）。
- 双轴模型：分类可多选（个人信息、敏感个人信息、经营、财务、研发、商业秘密等），安全等级单选（一般数据、重要数据、核心数据）。
- 高置信度普通分类可自动生效并进入抽样复核；AI 对重要/核心数据只能提出候选，必须由数据负责人确认、数据安全负责人批准后生效。
- 资产级等级默认继承最高数据项等级；系统不得自动降级，降级需重新扫描、说明变化并通过复核批准。
- 分类等级提高或新增敏感项时，关联的数据产品、授权、出境场景、脱敏、加密和水印策略进入待复核。
- 分类分级报告固定扫描范围、版本、覆盖率、规则/模型版本、结果、冲突、影响和审批；状态为草稿/待复核/已批准/已失效，已批准不可覆盖。

**FR-04 防护策略与访问控制**
- 防护策略把生效分类分级记录映射到生命周期保护要求、责任人、审批和执行证据。
- 支持人员、部门、内部系统、外部机构对资产/字段/API/文件的用途、范围、期限、配额策略。
- 支持越权访问、高频下载、异常交换等监控规则、安全信号和风险清单；策略例外必须记录申请人、范围、原因、补偿措施、有效期和审批。

**FR-05 脱敏管理**
- 支持静态脱敏和动态展示脱敏；支持掩码、泛化、替换、哈希、令牌化等规则类型。
- 预览仅使用虚构或脱敏样例，不展示真实敏感数据。

**FR-06 加密管理**
- 支持传输、存储和字段级加密策略；记录算法、适用范围、密钥引用、轮换状态、到期提醒。
- 系统不得保存真实密钥、私钥或可还原凭证；加密覆盖率只能基于模拟执行证据计算。

**FR-07 数据水印**
- 支持报告/预览/导出文件的显式水印，和下载文件/结构化数据副本的隐式追踪水印。
- 水印模板可包含使用方、授权、用途、时间和追踪 ID。

**FR-08 数据出境合规评估**
- 以出境场景作为管理对象，记录境内处理者、目的、必要性、数据范围、分类版本、自然人数、境外接收方、国家/地区、渠道、频率、期间和保护措施。
- 按自当年 1 月 1 日起的自然人去重口径记录累计个人信息和敏感个人信息数量。
- 引擎输出“信息不足、可适用豁免、建议标准合同或认证、应申报安全评估、高风险待专家审查、内部评估完成”等状态。
- 法务合规和数据安全双重审批后场景才可进入“内部允许执行”，该状态不代表监管批准。
- 目的、接收方、数据范围、安全等级或规则版本实质变化时触发重新评估；新规则不回写历史报告。

**FR-09 数据安全审计与自动报告**
- 覆盖过程审计、规范审计、合规审计和供应商审计。
- 数据访问、流转、交换、操作和执行的原始事件由来源域拥有；数据安全模块只按稳定事件 ID 建立证据目录，不复制或修改来源事件。
- “一键生成”自动完成证据汇聚、完整性检查、指标计算、异常聚类、根因候选和报告草稿；证据不足时报告必须标明限制。
- 审计人员独立复核并形成结论；数据安全负责人负责整改分派，不得改写审计结论。
- 报告批准后冻结；审计问题需独立复核通过后方可关闭。

**FR-10 安全事件响应**
- 区分安全信号、疑似安全事件和安全事件；被排除案件仍保留研判依据。
- 安全事件使用 S1 特别重大、S2 重大、S3 较大、S4 一般四级严重性。
- 事件记录使用“研判、处置、恢复、通知、复盘”五阶段轻量 SOP；每阶段记录负责人、状态、结果、时间和附件。
- S1/S2 必须完成复盘和独立关闭复核；紧急处置可先执行，但必须补录原因和授权。
- 通知义务由事件事实、数据类别/等级、行业、法域和规则版本生成，状态为“需要通知、无需通知、待法务判断”。
- 支持演练计划、结果、问题、改进和知识库沉淀。

**量化指标（17 项）**

分类分级覆盖率、分类复核及时率、分类识别误报率、分类等级过期率、保护策略覆盖率、异常行为发现率、风险整改按期率、平均响应时间、平均恢复时间、审计证据完整率、安全审计覆盖率、审计整改关闭率、重大问题复发率、出境评估覆盖率、合规规则过期率、待重新评估场景数、DCMM 控制项证据覆盖率。

> 当来源缺失、分母不完整或证据不可校验时，指标显示“未知/证据不足”，不得用 0 或 100% 代替。

**关键约束**
- 当前原型只模拟扫描、策略执行、审计、出境评估、事件和通知结果，不执行真实安全控制。
- 不实现真实 IAM、KMS、DLP、加密、脱敏、水印、异常检测或安全态势引擎。
- 不进行真实监管申报、标准合同备案、认证申请、通知发送或外部审计服务。
- 不保存真实个人信息、敏感数据、密码、token、密钥、私钥或完整连接串。

**当前实现状态**：25 个功能页、六分域 SQLite mock 与三级菜单已实现。

- 外部数据源注册和评估流程：复用 CRM 外部商机同步模式，记录外部数据源基本信息、供应方、数据范围、接入方式、评估结果和审批状态。
- 外部数据质量评估和 SLA 管理：对外部数据设定质量维度和 SLA 指标，定期评估并记录达标情况；不达标触发整改或供应方协调。
- 外部数据接入合规审查：审查数据来源合法性、使用授权范围、是否涉及个人信息或重要数据；与数据安全模块（模块 11）的分类分级和合规审查联动。

**关键约束**：不接入真实外部数据源；合规审查复用数据安全模块的规则包和分类分级记录，不重复维护；外部数据不自动进入资产目录，需经注册评估审批后纳入。

**当前实现状态**：规划中，尚未建立独立外部数据管理模块。

### 模块 16 · 数据治理智能化与成熟度自评估

**原始需求**

- 数据治理规则自优化（基于反馈的自动调参）
- AI 辅助数据管理决策（智能推荐治理策略）
- 数据能力成熟度自评估工具
- 行业数据管理标准参与制定

**模块定位**
在 DCMM 2.0 L4 量化管理级基础上，引入治理规则自优化、AI 决策辅助、成熟度自评估和标准参与能力，支撑组织持续优化和标准贡献。

**核心功能需求**

- 数据治理规则自优化：基于质量、落标、安全等反馈数据，AI 自动调整治理规则参数并记录调参依据和效果；调参结果需责任人确认后生效。
- AI 辅助数据管理决策：根据组织现状和差距，AI 智能推荐治理策略、改进优先级和资源分配建议；建议为 mock 待确认。
- 数据能力成熟度自评估工具：对照 DCMM 九域 33 个能力项，组织自评估就绪度并生成差距清单和改进事项；自评估结果不等于认证结论。
- 行业数据管理标准参与制定：登记组织参与国家/行业标准制定的项目、角色、阶段、人员、时间和证据引用；与数据标准模块的标准参与证据联动。

**关键约束**：规则自优化和 AI 决策均为 mock 建议待确认，不自动改写正式事实；自评估工具不输出 DCMM 认证结论或通过概率；标准参与证据复用数据标准模块的登记记录，不重复维护。

**当前实现状态**：规划中；数据标准模块已支持标准参与证据登记，其余能力待建设。
