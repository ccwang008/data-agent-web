# Data Platform · 大数数据平台产品范围

## 产品定位 · Positioning

大数数据平台面向企业数据工程、数据治理、业务分析、应用开发和 AI 应用团队，提供从数据接入到数据资产消费的统一工作台。核心结果不是“把数据存起来”，而是让数据可发现、可理解、可授权、可调用、可追踪。

当前仓库承载本地全栈原型和交互验证，产品能力按“SQLite 持久化 mock 已实现 / 部分实现 / 规划中”标识。业务数据和执行结果保持 mock 语义并保存到项目本地 SQLite；真实连接器、计算引擎、服务网关、权限中心和生产级监控不属于当前前端仓库的实现范围。

## 能力地图 · Capability Map

### 1. 数据资产运营 · Data Asset Operations

将治理后的数据转化为可发现、可使用、可运营的数据资源。

- **资产目录**：统一管理数据集、数据表、指标、标签和数据服务；支持检索、详情、申请、授权、使用追踪。
- **数据价值评估**：从使用热度、质量、时效性、覆盖度、业务贡献等维度形成价值评分和分层运营视图。
- **数据服务**：把数据能力封装为业务系统和 AI 可调用的服务。
  - 服务 API 创建：定义输入、输出、参数、协议、版本和 SLA。
  - 服务编排：组合数据查询、指标计算、治理规则和外部能力。
  - 服务发布：测试、审批、版本发布、下线和回滚。
  - 服务调用管理：调用方授权、限流、配额、日志、用量统计和异常追踪。

数据服务调用链应遵循：

```text
业务系统 / AI
      ↓ 鉴权、配额、审计
服务网关 / 数据服务 API
      ↓ 服务编排与参数校验
数据资产目录、指标、标签、湖表、计算任务
      ↓
数据湖 / 外部数据源
```

### 2. 数据集成 · Data Integration

- **数据源**：数据库、文件源、本地文件、消息队列、API；支持新增、查看、编辑、删除、连接测试和状态管理。
- **数据同步**：全量、增量、CDC、实时同步；支持源端/目标端、字段映射、调度策略、失败重试和运行记录。
- **共享交换**：API 交换、文件交换、库表交换、消息交换；支持交换配置、审批、传输状态、失败重试和审计。

当前前端入口：`/data-source/sources`、`/data-source/sync`、`/data-source/exchange`。

### 3. 数据湖 · Data Lake

统一管理企业结构化和非结构化数据。

- **统一数据存储**：数据表、文件、图片、视频、日志、文档等统一纳管；支持数据分层和生命周期管理，包括冷热分层、归档、清理。
- **湖表管理**：表建模、湖表管理、 Schema 管理、版本管理和 ACID 事务支持。
- **分层与容量**：展示存储层级、容量占用、增长趋势、冷热数据分布和生命周期策略。

当前前端入口：`/data-lake/storage`、`/data-lake/tables`、`/data-lake/capacity`。

### 4. 数据治理 · Data Governance

提升数据的可信度、可理解性和规范性。

- **元数据管理**：技术元数据、业务元数据、元数据检索、血缘关系和数据地图。
- **数据质量管理**：质量规则、质量评分、完整性/准确性等指标、任务执行和异常监控。
- **数据标准管理**：业务术语、指标定义、标准版本、责任人和标准审批。

当前前端入口：`/data-governance/metadata`、`/data-governance/quality`、`/data-governance/standards`。

### 5. 数据开发 · Data Development

面向数据工程师提供开发任务工作台：

- 可视化 ETL 开发：以 DAG 为核心，拖拽数据源、转换、清洗、聚合和输出节点，支持字段映射、节点校验、预览和节点级运行反馈。
- SQL 开发：以脚本为核心，支持上下文、参数、编辑、校验、语句级试运行、结果、错误定位和版本管理。
- Notebook：以有状态单元格文档为核心，支持参数、运行时、执行顺序、富输出、检查点和可复现任务发布。

三种开发方式共享任务身份、不可变发布版本、运行记录、审计和血缘契约，但使用独立编辑器。数据开发任务应能被调度引擎通过 `artifactType + artifactId + version` 稳定引用，并产出可追踪的输入、输出、日志和血缘信息。当前前端入口：`/data-development/etl`、`/data-development/sql`、`/data-development/notebook`；列表、专业编辑器、版本和执行状态已使用 SQLite 持久化 mock，跨域血缘与审计跳转按 feature spec 继续深化。

### 6. 调度引擎 · Scheduler

负责数据集成、数据开发、数据处理、数据质量校验和数据服务任务的统一编排与运行管理。

- **调度任务**：用画布拖拽创建任务；支持缩放、平移、节点增删改查、节点连线、节点配置和节点结果查看。
- **任务类型**：覆盖数据集成、数据开发、数据处理、数据质量校验、数据服务等。
- **任务监控**：查看运行状态、进度、耗时、日志、重跑/停止等运行管理信息。

当前前端入口：`/scheduler/tasks`、`/scheduler/editor`、`/scheduler/monitor`。画布使用 `@xyflow/react`，生产执行引擎尚未接入。

### 7. 运维与监控 · Operations & Monitoring

保障数据平台稳定运行，统一提供：

- 任务监控：任务成功率、延迟、失败、重试和告警。
- 数据链路监控：数据源、同步、湖表、治理、服务之间的链路状态和血缘影响。
- 数据质量监控：质量规则执行、评分变化、异常数据和整改闭环。
- 计算资源监控：计算集群、作业资源、容量、队列和成本。

当前前端入口：`/ops-monitor/tasks`、`/ops-monitor/lineage`、`/ops-monitor/quality`、`/ops-monitor/resource`；跨域告警和资源采集保持 mock。

### 8. 数据安全 · Data Security

- **安全总览**：按 DCMM 第4级就绪度展示数据合规、安全防护、安全审计三域能力、量化指标、证据缺口和整改待办。
- **数据合规**：维护版本化合规清单、合规审查、个人信息、重要数据和数据出境评估；首版使用中国大陆规则基线。
- **分类分级**：以数据项为最小对象，使用多选分类与一般/重要/核心单选等级双轴模型；AI 可自动识别普通分类，但重要/核心数据必须经职责分离审批。
- **安全防护**：覆盖防护策略、访问控制、脱敏、加密、数据水印、安全监控和风险评估，并记录执行证据。
- **安全审计**：覆盖过程、规范、合规和供应商审计；引用来源域访问、流转、交换、操作和执行证据，一键生成待复核报告草稿。
- **事件响应**：维护安全信号、疑似事件和安全事件，使用 S1–S4 严重性及研判、处置、恢复、通知、复盘五阶段轻量 SOP。

安全能力必须贯穿资产申请、服务调用、数据交换、开发运行和运维审计，而不是只在单独页面展示。当前已实现安全总览、合规、分类、防护、审计和事件响应六个能力域共 25 个 SQLite mock 页面；完整一级/二级/三级菜单与路由见 [`features/data-security/design.md`](../features/data-security/design.md)。

数据安全工作台用于 DCMM 第4级就绪度、内部管理和证据支撑，不替代 DCMM 认证、外部审计、监管批准或法律意见。当前原型只保存脱敏 mock 状态和证据引用，不执行真实扫描、IAM、KMS、脱敏、加密、水印、监控、通知或监管申报。

## 产品对象 · Core Objects

| 对象 | 说明 |
|---|---|
| 数据源 | 外部数据库、文件、消息队列、API 或本地文件的连接与凭证引用 |
| 数据集/数据表 | 数据湖或外部系统中的可管理数据对象 |
| 指标 | 经过定义、审核和版本化的业务度量 |
| 标签 | 描述主题、敏感级别、业务场景或运营属性的分类信息 |
| 元数据/血缘 | 描述数据结构、语义、责任和上下游依赖 |
| 数据服务 | 对数据查询、指标、处理或编排能力的稳定服务封装 |
| 调度任务 | 可配置、可执行、可监控的 DAG 任务 |
| 质量规则 | 对完整性、准确性、及时性、一致性等质量维度的可执行约束 |
| 生效分类分级记录 | 经置信度、复核和批准要求验证，可供保护、出境和审计引用的版本化数据项结论 |
| 数据保护策略 | 依据分类分级和使用场景形成的访问、脱敏、加密、水印或监控要求及执行证据 |
| 出境场景 | 由处理者、目的、数据范围、境外接收方、传输方式和期间共同界定的持续性评估对象 |
| 安全审计证据 | 指向来源域访问、流转、交换、操作或执行事实的稳定、脱敏、可校验引用 |
| 安全事件 | 经确认并进入研判、处置、恢复、通知和复盘流程的数据安全案件 |

## 验收原则 · Acceptance Principles

新增模块或页面至少应满足：

1. 页面入口、菜单项、路由和 feature spec 一致。
2. 列表、详情、创建/编辑、删除/发布等操作有明确的状态反馈。
3. 重要对象具备责任人、状态、更新时间、版本或审计信息。
4. 涉及数据调用的能力说明调用方、授权、参数、结果、失败和追踪方式。
5. mock 数据结构应能平滑替换真实 API，并通过 SQLite scope 持久化，不把业务数据写死在通用组件中。
6. 数据资产、同步、治理、调度和服务之间保留可扩展的 ID、版本、血缘和任务关联字段。
7. 数据安全结论必须绑定规则、对象和证据版本；未知或证据不足不得显示为零风险、符合或已认证。
8. 页面按核心业务任务设计专属信息架构，不得以“顶部通用指标卡 + 筛选 + CRUD 列表/表格”作为跨页面默认模板；指标与列表仅在确有决策或批量浏览需求时作为局部结构使用。

## 非目标 · Out of Scope for Current Frontend

- 不在本仓库实现真实数据库/消息队列/对象存储连接器；本地 SQLite 仅用于原型状态存储。
- 不在本仓库实现生产级 CDC、实时计算、ACID 存储引擎或 Notebook 执行内核。
- 不在本仓库实现完整 IAM、KMS、API Gateway、告警平台和资源调度后端。
- 不用前端 mock 页面替代真实的权限校验、加密和审计保证。
